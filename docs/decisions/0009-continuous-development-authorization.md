# ADR-0009：完成准备后连续开发的条件授权

## 用户确认

本会话最新原文：“可以。先完成所有的准备工作。然后开始开发。无需要人为决策时，不用停止。”前序原文：“需要的工具和Skill，你自己安装 ，但应该在最终产出的Skill的README.md中明确说明。”

授权涵盖现有#3–#13规划集合及M0–M4的准备、必要工具/Skill安装、独立试验、CI准备和准备通过后的连续开发。无需逐工具、逐任务、逐里程碑重新请求同一批准。重大领域变化/不可自行裁定的范围成本取舍仍交用户；不自动归档，Issue事件仍不启动任务。

## 与既有工件的关系

此前planning-only及“准备后另取开发批准”是历史状态，本决策替代该授权限制；用户约束、技术就绪和独立验收门禁没有取消。不得让旧令牌或本授权绕过未通过的技术/隔离检查。AGENTS只作为文档入口，各类规则分开维护。

状态分别记录：development_authorized=true；readiness_complete=false；isolation_ready=false；implementation_started=false。这不是撤回授权，条件满足即可连续实施，无需再批准。当前技术设计未全部冻结，不写产品或隐藏测试来伪造准备通过。

## 当前真实阻塞

共享执行环境不能隔离五角色；用户映射只支持一个身份，setpriv/unshare/bwrap均未成功，Landlock接口不可用。没有可用容器运行器；当前GitHub连接器不提供独立私有验收设施/密钥的部署管理入口。诊断见本轮readiness记录。

可独立继续：治理文档、环境依赖、固定真实项目的公开工具能力试验及契约收敛。必须等待真实边界：隐藏用例编写、独立产品编码/测试/验证流水线；不能拿当前原生子代理共享文件系统冒实际权限隔离。工具能力试验不是产品验收。

## 依赖与README

实际安装版本及验证范围记录于本轮环境档案，最终Skill README必须写必需/可选依赖、来源/版本、安装与自检、平台范围、缓存和写入行为、联网/模型配置及失败限制。不在产品未实现时宣称Skill已可用，不泄漏凭据/私有用例。
