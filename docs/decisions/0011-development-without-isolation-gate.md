# ADR-0011：不以盲编写隔离阻塞开发

日期：2026-11-05。状态：用户已明确确认的工作政策；隔离证据仍按事实记录。

## 决定

用户要求：“先放宽 双向盲编写和私有验收隔离门禁。保证开发工作可以进行。”据此，从本决策起，双向盲编写、正式AI角色工具入口及私有验收隔离不再是开始或继续产品开发的前置门禁。按现有 OpenSpec tasks 和 ADR-0009 授权继续工作，不要求用户重复批准。

当前会话可在现有共享云工作区进行实现、开发侧测试、公开CI和审核。所有参与者可能读取工作区中可见内容；不得把提示词、子代理角色名、分目录或 worktree 描述为强制访问隔离。需真实隔离的设施尚不存在时，不在其中声称已执行盲测或私有验收；如果没有可运行的私有suite，就明确标注该验收未运行，并以公开契约、开发侧测试和可用的固定CI检查推进相应任务。

## 证据和报告

本决定改变工作授权和启动门槛，不改变技术事实。历史隔离失败、托管合成probe通过及其有限范围均保留，不重写为通过。每项工作区分实现/开发侧检查、公开CI、独立审查、私有验收和隔离证据；只报告实际运行的项目。未执行的私有验收不得勾作已通过，发布或对外质量声明须说明其缺失。

若后续任务明确要求保密用例、独立盲验或受限角色身份，则该项工作须等能提供相应隔离的执行方式；这不阻塞其他开发任务。产品、规格及验收任务继续按原tasks维护，不为本政策复制第二份产品计划。

## 保持有效的约束

ADR-0009 的连续开发授权继续有效。领域决策、重大范围取舍、凭据和私有资料保护、不自动归档、Issue事件不触发开发等原规则继续适用。ADR-0010 描述的双向独立编写作为首选质量模式保留，但在访问控制未验证的当前环境下属于目标而非通用开发门禁。
