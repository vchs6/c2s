# 产出物使用说明核验

依据用户要求及随后澄清，交付仅说明使用当前产出物时需要的本地工具、其他项目分析Skill和安装责任，不列开发用Skill作为运行前提。不修改产品代码、工具矩阵、点亮状态、宿主注册清单或当前N1行为。

## 文档核对

新增`skill/使用说明.md`，仓库README与Skill README均提供入口；Skill README的最小安装不再混入Node/npm和开发校验命令。核对实际CLI/API、最小依赖、工具矩阵与外部执行入口：

- 必需其他项目分析Skill为零；Serena/GitNexus/配套建图Skill保持candidate，不能写成安装后即接入。
- 最小Python依赖来自requirements-skill.txt；当前即使只分析Python也按完整最小依赖安装。
- Cargo仅作为原生workspace能力的条件依赖；Rust静态解析不依赖Cargo。
- 已有Code Review Graph结构化响应的导入不依赖本机图包或配套Skill；C2S不自带建图后端执行命令。
- 代理代装的前提是可操作终端、下载网络和写权限；代理所在云环境与用户个人电脑不能混同，CLI本身不自动安装。
- 仓库没有生产Skill的SKILL.md发现清单和Python安装包配置，当前运行形态为仓库CLI/API，不能声称已实现宿主自动注册。

## 实际执行

用真实Python3.12.5标准venv在临时目录新建环境，再通过pip从公开包索引安装requirements-skill.txt（安装时禁用下载缓存以避免宿主缓存写权限影响）。三个直接依赖实际为jsonschema4.26.0、tree-sitter0.26.0、tree-sitter-rust0.24.2，未安装code-review-graph。

从新说明提取Python自检正文，在该解释器执行通过；SQLite标准库版本3.46.0。查询子进程PATH只保留该venv/bin，使Node/npm/Git/Cargo/CodeGraph/ast-grep/Semgrep均不可见，不调用其他Skill：

| 场景 | 结果 |
| --- | --- |
| 没有.git的Python目录，查询modules并写SQLite | 退出0，obtained，1个目标，无诊断 |
| Rust目录，查询functions，Cargo不可见 | 退出0，obtained，取得run函数，无诊断 |
| 导入已有图JSON，本机未装CRG | 退出2，partial，取得1个目标、1份原始工件，保留GRAPH_INDEX_FRESHNESS_UNVERIFIED及算法静态缺口 |
| 请求workspace-members，Cargo不可见 | 退出2，not_acquired，WORKSPACE_NOT_ACQUIRED与TARGET_NOT_ACQUIRED；没有伪造原生元数据 |

所有档案文件核对为SQLite格式，输出置于输入目录外；查询前后来源文件摘要一致。三个修改文档中的本地Markdown链接均能解析。这里只核验安装说明与声明的最小使用边界，不重新声称所有真实项目、宿主Skill注册或跨平台运行已通过。
