# 领域基础

本文件整理当前模型语境与阅读入口，不复制完整规格或把研究草案升为基线。权威依次为最新用户决定、正式OpenSpec规格、获准变更、设计研究。已确认来源见ADR-0001至0008；开发授权见ADR-0009。

## 统一语言与区别

| 术语 | 当前约束 | 不得混同 |
| --- | --- | --- |
| 主体 | 同一主体跨语义尺度保持单一身份 | 名称、路径、内容摘要、工具图UID不单独替代身份 |
| 事实 | 关于主体的带类型语义陈述，保留条件、来源及取得边界 | 未解释源码片段、模型猜测、工具置信度不是自动裁真的依据 |
| 工程Project | 工程边界与身份需要明确依据 | 目录、Git仓库、workspace成员、包名不自动等同Project |
| Workspace成员 | 工程组织/协作关系 | 目录嵌套不是成员，成员关系不推所有权转移 |
| 构造目标/产物 | 目标声明、依赖解析、实际生成分别表达 | target平台、BuildTarget和已观测产物不是一个概念 |
| 查询顶层 | 符合本次请求目标的完整顶层事实 | 不是固定E编号、目录层数，也不递归附送关联对象 |
| 缺口 | 请求所需但未取得的内容及原因 | 未展开、未取得、不支持、不适用、已确认不存在分开 |
| 事实增量 | 固定项目输入中补充尚未完成的所需事实 | 不是分析中源码热更新 |

## 语义尺度与不变量

ADR-0012确定语义实体为领域事实的组织主轴。E0工程组织与协作、E1构建装配与交付、E2程序结构与接口、E3操作行为契约、E4实现算法与局部语义保留为可组合观察视角，不是实体类型、DDD架构层、强制包含树或默认细化链。被分析项目不必采用DDD。

身份不随工具、层或宿主平台重键；跨层用类型引用。目录归属、workspace组织、构建依赖和调用分别定义。未知不当否定、声明不当观测、局部线索不当完整语义。工具输出和LLM结果都需保留来源与局限，不能以工具多数票裁真。

查询返回范围内所需顶层完整结果，内部必要取证不等于递归响应；双输出表达同一事实及缺口。同主体重复查询复用适用成果，仅补当前未完成内容；指定目录全部内容是范围，不等于提前构造全部事实。

## 实现设计边界

原模型A是五视角目录方案的历史规划选择；现行公共领域模型按ADR-0012和语义实体profile定义。旧目录只在兼容范围继续使用；不在此新增Schema。聚合、限界上下文、事务、数据库、获取器实现语言不是五层自动推得的结论。第三方代码图社区不是DDD边界；原生包ID、图节点ID通过适配关联，不能直接冒领域身份。

正式规格：`openspec/specs/semantic-fact-model`、`semantic-fact-query`、`semantic-analysis-scope`、`lazy-semantic-fact-construction`、`semantic-analysis-quality`。完整Requirement/Scenario只维护在这些能力，避免双轨定义。

研究资料`drafts/software-semantic-domain-model.md`和`proposals/language-independent-layered-semantic-model.md`仍保留原性质；不得依据其旧分类覆盖当前基线。跨次更新政策和逐语句事实粒度专项保持延期，不因开始开发自动引入。
