# 语义实体中心领域模型

状态：由用户于 2026-11-07 批准进入实施；规范性定义见 OpenSpec 主规格 `semantic-fact-model`、`semantic-fact-query` 与 `lazy-semantic-fact-construction`。

## 目的与边界

本模型表达软件项目解决什么问题、提供哪些能力、处理哪些数据以及实体之间如何关联。源码结构用于说明这些语义对象如何被实现、约束、表示或生成，不直接决定语义实体的种类和边界。模型是从代码、少量说明文档、测试及可用工具证据逆向推导的记录；不能保证自动还原全部业务意图。

E0 工程组织与协作、E1 构建装配与交付、E2 程序结构与接口、E3 操作行为契约、E4 实现算法与局部语义是事实的观察尺度，不是实体类型，也不构成强制包含树。领域驱动设计（DDD）用于统一语言、身份和不变量，不预先规定聚合根、存储表或服务边界。

## 语义实体

语义实体是具有稳定身份、可被独立引用、复用或查询的软件项目概念。首期类型包括：

| 类型 | 含义 |
| --- | --- |
| `Project` | 被分析的软件项目 |
| `Module` | 按职责组织其他实体的语义模块，不等同于目录、命名空间或语言模块 |
| `Capability` | 项目提供的能力或职责，可跨模块组织 |
| `DataEntity` | 项目创建、读取、维护或交换的信息概念 |
| `ComputationEntity` | 项目执行的计算、操作或业务能力 |
| `ExternalActor` | 与项目交互的用户、系统、设备或外部服务 |
| `TestEntity` | 具有场景、断言或验证目标的测试对象 |

实体由分析范围内持久注册表分配 `EntityId`。名称、路径、行号、内容摘要和工具节点标识都不能单独作为身份。源码移动、重命名或注册表丢失时，只提出连续性候选；缺少显式映射或强证据时保留独立身份并标注 `continuity_unresolved`（连续性未决），不自动合并。实体身份与源码构造身份分离。

## 属性与子实体

`EntityAttribute` 默认是拥有实体描述中的值对象，不另建实体身份；只有在可独立引用、跨实体复用或具有独立生命周期时才提升为实体，并保留 `promoted_from_attribute` 来源映射。

属性至少区分语义名称/别名、语义类型、实现类型参考、值域、基数/可选性、约束及证据。实现类型不等于语义类型：`String` 本身不能证明业务含义或有效值域。值域可表示有限集合、区间、格式/谓词约束、引用类型或未知/不完整状态，并注明其证据属于声明、代码校验、规范要求还是运行观察。有限样本不能证明完整值域。

详情查询必须一次返回目标实体全部已取得的自身属性及缺口；这是描述完整性，不是对业务属性穷尽性的证明。子实体通过关系返回引用；只有请求明确展开时才返回其自身完整属性。引用类型优先关联独立 `DataEntity`，不复制其完整描述。

## 关系与事实主张

`EntityRelation` 是带类型、有方向的实体关联，可带条件、证据和覆盖状态。首期关系包括 `defines`、`groups`、`contains`、`belongs_to`、`depends_on`、`uses`、`produces`、`transforms`、`interacts_with`、`realized_by`、`verified_by`。谓词目录约束允许的端点类型。目录包含不自动证明业务包含，函数调用不自动证明业务依赖。

关系及属性值由 `FactClaim` 表达，并保留来源、取得方法、证据角色、推导链和条件。主张认识状态（已获支持、暂定、冲突）、获取覆盖（已取得、未取得、不支持、不适用）、响应呈现（已呈现、未展开）与新鲜度（当前、过期/待复核）必须正交记录。冲突证据不得丢弃；无证据解释须标为待确认。

## 源码构造、实现机制与映射

`SourceConstruct` 保留源语言、语法种类、源码位置、声明形状/签名及源码包含关系，可表示模块、类、字段/属性、函数/方法、枚举/成员、泛型、宏定义/调用/展开、注解/应用、λ匿名函数和闭包等。宏、泛型等是上游实现机制，不意味着迁移到目标语言时必须照搬。

`ImplementationMapping` 显式关联语义实体、属性或关系主张与源码构造，说明其声明、实现、表示、约束、生成或调用角色。允许一对多、多对一、部分、间接、冲突、未解析和无映射。类可以通过字段实现数据属性、通过方法实现计算职责；一个语义实体也可以横跨多个源码构造。没有语义映射的源码构造仍可保存和查询。

## 测试实体

测试场景是独立的 `TestEntity`。`VerificationRelation` 将其关联到被验证的语义实体，或具有稳定引用的行为/属性主张；测试入口另行映射到源码构造。测试函数身份不等于测试实体身份，存在测试代码也不自动证明覆盖某业务目标。

## 查询规则

- 项目或模块清单返回直接关联实体的身份、名称、类型、可选摘要和关系，不递归展开实体详情。
- 实体详情一次返回目标自身所有已取得属性、直接关系、证据和缺口；关联实体仅作为引用返回。
- 明确要求子实体完整描述时，逐个将这些实体作为详情目标返回其全部自身属性，不递归展开其关联子图。
- 实现查询返回源码构造、映射角色、定位、证据和未解析部分；调用目标不自动展开。
- 测试查询返回直接验证关联及测试入口；未知目标和获取缺口如实报告。
- 可读报告和结构化输出必须来自同一查询结果，事实范围和缺口一致。

## 迁移原则

新档案 `semantic-entity-model-1` 是目标公共模型。迁移期间保留旧档案默认写入路径，新档案只在隔离档案/夹具验证；完成真实 Python、Rust 支持范围全集遍历、查询/仓储回读、兼容投影和成本测量后，才允许将新档案设为默认写入。旧完整模型以只读兼容接口和确定性投影保留，无法映射的数据必须报告损失或缺口。M1 独立入口继续保留。任何失败均保持旧默认路径并允许回滚。

结构及引用校验、真实项目遍历和证据回读只能证明契约合法、覆盖范围及数据保真，不能证明推导出的业务解释必然正确。未测的性能、平台或大语言模型词元数据必须标为未测。
