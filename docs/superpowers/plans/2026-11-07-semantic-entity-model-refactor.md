# 语义实体模型重构实施计划

> **供代理执行者：** 必需子技能：使用 `superpowers:executing-plans` 按阶段实施。本计划中的步骤用复选框标记；OpenSpec 变更 `redesign-semantic-entity-domain-model/tasks.md` 是唯一权威进度表，本计划复选框不用于另行报告完成状态。

**目标：** 将项目语义事实的公共模型、仓储和查询路径重构为以语义实体、属性、关系、证据及源码实现映射为中心，同时保留旧档案的确定性兼容能力。

**架构：** 先冻结领域语言和版本化契约，再把语言工具输出规范化为语言无关源码构造，并基于证据构造实体主张。实体注册表、模型档案、查询和兼容投影分层实现；完成真实 Python 与 Rust 项目的支持范围全集遍历后，才切换默认档案。

**技术栈：** Python 3、SQLite、JSON Schema、现有 Python AST 与 Rust Tree-sitter/Cargo 获取器、仓库现有测试和 OpenSpec 校验工具。

**规格：** `openspec/changes/redesign-semantic-entity-domain-model/`；领域设计：`docs/superpowers/specs/2026-11-07-semantic-entity-domain-model-design.md`。

## 全局约束

- 语义实体身份由指定分析范围的持久注册表分配；名称、路径、行号、摘要和工具节点标识不能单独作为身份。
- 事实主张、获取覆盖、响应呈现及缓存新鲜度分别表达；无证据的推断必须保留为暂定、冲突或缺口。
- 类、枚举、泛型、宏、注解、λ匿名函数和闭包属于源码构造或实现机制，不能直接充当语义实体类型。
- 项目、模块、能力、数据、计算、外部参与者和测试实体按显式关系表达；源码目录和构建包不能自动当作语义模块。
- 单实体详情返回目标实体全部已获取属性；其子实体默认只列引用，除非请求明确展开。
- 旧 `semantic-fact-model-1` 在迁移阶段保持原默认写入；通过完整验证后才切换到新档案，旧档案成为只读兼容端口，M1 入口独立保留。
- 仓库自有脚本和测试使用 Python 3；不宣称未实际验证的语义正确性、平台支持或私有验收结果。
- 文档使用中文；代码标识符、路径、协议字段及 OpenSpec 必需结构标题保留约定拼写。

## 评审重点

- 注册表重建、并发重复注册或丢失时不得静默重键或错误合并；由 1.3、3.1 的身份测试覆盖。
- 相同源码结构可支持不同语义解释，工具输出不能直接成为业务真相；由 2.1、2.2 的证据和无映射夹具覆盖。
- 成员列表与实体详情的展开边界不得导致属性遗漏；由 4.1、4.2 的查询与双输出一致性测试覆盖。
- 旧记录不能因名称或路径被猜测升级，投影不能静默丢字段；由 3.2 的往返及损失诊断测试覆盖。
- 支持范围全集遍历必须逐项验证写入、回读和查询，不得抽样替代；由 5.1、5.2 的固定真实项目清单覆盖。

## 实施阶段

### 阶段一：领域词汇与公共契约（OpenSpec 1.2–1.3）

**文件边界：** 新增 `docs/domain/semantic-entity-model.md` 和新决策记录；更新三个主规格；新增 `contracts/semantic-model/` 版本化契约、`src/c2s_semantic_contract/validation.py` 与 `tests/semantic_model/`。

- [ ] 对每个主规格先添加满足该领域要求的正反测试夹具；夹具覆盖实体/属性、关系端点、证据状态、观察视角、身份范围和迁移映射。
- [ ] 运行规定的 `unittest` 命令，确认新增规则在实现前产生失败；保留已有规格校验作为基线。
- [ ] 写领域模型及新决策记录，精确说明取代的旧决策范围，不改写既有 ADR。
- [ ] 实现 `semantic-entity-model-1` 的目录、JSON Schema 和不变量校验；持久身份注册表与候选连续性状态必须有明确契约。
- [ ] 运行模型正反测试、`npm run validate` 和严格 OpenSpec 校验；只有输出成功且夹具断言完整才完成 OpenSpec 1.2–1.3。

### 阶段二：源码构造与证据驱动构造（OpenSpec 2.1–2.3）

**文件边界：** `skill/src/c2s_skill/acquisition.py`、`capability_matrix.py`、相应语言适配器、构造器及 `skill/tests/`。

- [ ] 为 Python/Rust 源码构造、成员关系、字节跨度、来源版本和解析缺口添加失败测试；覆盖类/结构体/字段/方法/函数/枚举/泛型/宏/注解/匿名函数/闭包。
- [ ] 实现统一 `SourceConstruct` 以及工具输出解析边界；校验工具私有类型不泄漏到公共档案，跨度和摘要可从源码复核。
- [ ] 为证据到语义实体、属性值域、关系和映射添加失败测试；覆盖裸 `String`、枚举/范围/校验、冲突、同名实体和无语义映射源码构造。
- [ ] 实现证据驱动构造，并把测试实体与其验证的实体/主张分开建模；用多测试验证同一主张及未知目标夹具验证关系闭合。
- [ ] 运行适配器与构造器的定向测试及 Skill 全套测试；按 OpenSpec 2.1–2.3 逐项核实源码定位、证据与缺口。

### 阶段三：SQLite 仓储与旧档案互通（OpenSpec 3.1–3.2）

**文件边界：** `skill/src/c2s_skill/semantic_store.py`、既有仓储接入点和仓储测试。

- [ ] 先为原子注册、并发身份复用、完整往返、引用闭合、冲突保留、崩溃回滚及档案隔离编写失败测试。
- [ ] 实现新档案隔离的实体、属性、关系、源码构造、映射、主张、证据、覆盖和注册表持久化。
- [ ] 为旧档案导入、确定性投影导出和不可映射字段诊断编写测试；孤立旧源码声明不得自动升级为实体。
- [ ] 实现旧档案兼容接口；验证重复导入可恢复、投影不静默丢字段且 M1 入口及旧默认写入路径不变。
- [ ] 运行新旧仓储测试及完整 Skill 测试，依据 OpenSpec 3.1–3.2 检查事务边界和数据保真。

### 阶段四：实体查询、实现视图与按需复用（OpenSpec 4.1–4.4）

**文件边界：** `skill/src/c2s_skill/query.py`、`algorithm.py`、查询投影、`skill/contracts/semantic-fact-query.schema.json`、命令行接入和对应测试。

- [ ] 为项目/模块成员清单、实体完整属性、明确展开、中文与结构化请求、未知及歧义目标编写失败测试。
- [ ] 实现查询目标解析和共享结果投影；验证 Markdown/JSON 的身份、属性、关系、证据和缺口逐项一致。
- [ ] 为算法步骤、调用、数据流、源码跨度和不透明缺口编写测试；实现步骤关联计算实体/主张，不把算法步骤创建成业务实体。
- [ ] 为覆盖复用、按需补全、版本失效、源码移动、注册表重建及连续性歧义编写测试；使用调用计数证明有效覆盖不重复解析。
- [ ] 运行查询、算法、契约与缓存/失效测试，并检查 4.1–4.4 的依赖和查询状态正交性。

### 阶段五：真实项目全集遍历和成本实测（OpenSpec 5.1–5.3）

**文件边界：** `docs/development/reviews/semantic-facts/` 下两份实体清单、成本对比报告及 Python 3 可复现脚本。

- [ ] 固定并记录 Click 与 regex 项目检出版本及环境，先验证遍历器会发现实体、属性、关系、实现映射、测试映射和缺口。
- [ ] 对 Click 的支持范围执行构造、校验、SQLite 写入、所有支持查询目标遍历和回读逐标识比对；输出完整清单，不以抽样替代。
- [ ] 对 regex 的支持范围执行同样全集流程，并额外检查 Cargo 工作空间、包、源码模块以及泛型/枚举/宏边界。
- [ ] 只有两项目逐项遍历成功后，才对相同请求、范围和环境测量旧新路径时间、存储与解析调用；LLM 未调用时写明“未测/无使用量”。
- [ ] 运行复测脚本并核对清单、回读和成本报告；覆盖口径不一致时不得宣称性能收益。

### 阶段六：文档、档案切换和交付验证（OpenSpec 6.1–6.3）

**文件边界：** `skill/README.md`、公共模型说明、迁移/回滚接入、最终验证报告。

- [ ] 根据实现和真实遍历结果更新中文 README、契约说明和查询示例，核验所有文档命令在当前环境可运行。
- [ ] 切换前检查两项目全集遍历、成本对照、查询/仓储/兼容测试和旧仓储备份；任一未过则保留旧默认写入路径。
- [ ] 满足全部前置条件后切换新档案为默认写入，验证旧完整档案只读、M1 独立入口不变、备份可读且可回滚。
- [ ] 运行 OpenSpec 严格校验、`npm test`、`npm run validate`、模型契约测试、Skill 测试、旧档案导出和两项目全集遍历。
- [ ] 形成中文交付报告，列明实际运行命令、证据产物、尚存限制和共享工作区隔离限制；不得把共享测试描述成私有盲验收。

## 计划自检

- 规格覆盖：OpenSpec 1.2–6.3 均映射到上述阶段；唯一进度状态仍由 OpenSpec `tasks.md` 管理。
- 步骤粒度：每个阶段先写失败测试、确认失败，再实现和运行验证；迁移切换单列为有前置条件的最后变更。
- 接口一致性：阶段二定义的 `SourceConstruct` 和实体记录供阶段三、四使用；阶段四结果由阶段五遍历，阶段五证据决定阶段六是否切换。
- 风险覆盖：身份连续性、证据边界、查询展开、兼容损失、全量遍历均有对应测试或真实项目核查。
