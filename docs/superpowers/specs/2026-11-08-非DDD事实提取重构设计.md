# 非DDD上游事实提取重构设计

状态：设计与任务分解交付，尚未执行本轮产品重构。依据ADR-0013及2026-11-08修订的正式规格。用户已选择在现有项目上重构，当前请求仅完成设计和任务分解。文中接口和版本选择是代理提出的技术设计，不冒称用户逐字段确认。

## 目标与约束

提取并按需查询上游项目/模块组织、语义实体及属性关系、源码实现参考、算法/伪代码和测试关联。记录直接来源、分析推导、覆盖与未决项。源码组织没有语义映射时仍可独立查询。不生成迁移方案、设计价值评价或上游组织动机解释。

首期Rust/Python；固定一次分析输入；指定目录内测试、示例、嵌套工程、隐藏及忽略文件均盘点，无法处理项披露。工具仅选择非商用可用组件，解析及真实输出验证后才能点亮。产品0.b.c，宿主与项目target分别取证。共享开发遵守ADR-0011，不将公开测试称作私有盲验收。

## 方案与取舍

采用在现有模块中渐进替换的方案：先新增有版本的公共数据协议，再打通来源组织、按需计划和存储查询，最后验证切换。整体重写会重复现有解析、证据和兼容工作；只更换DDD文字无法修复全仓构造、固定视角和来源组织丢失，因此不采用这两种路径。

CodeGraph 1.6.2已在临时副本索引Click/regex，但未有产品解析器及请求完整性证明；保留为可选关系后端。Python AST、Rust Tree-sitter、TOML/Cargo为基础组合，CRG继续可选。CodeGraph只在真实输出及覆盖收益验证后点亮，不以安装成功决定使用。

## 数据协议与版本

新增`semantic-entity-model-2`和`semantic-fact-request-2`/`semantic-fact-result-2`，保留v1只读兼容及旧CLI投影。选择新profile是因为新增独立来源事实、主张来源分类和细粒度覆盖会改变公共载荷；不在既有v1封闭Schema中暗加字段。新Schema放在`contracts/semantic-model/`，Skill请求/响应Schema放在`skill/contracts/`；公共定义只在此处维护。

模型v2保留v1实体、属性、关系、证据、映射及引用语义，并增加：

- `sourceRecords`：`recordId`、`kind`、`name`、`sourceConstructIds`、`parentRecordIds`、`relatedRecords`、`evidenceIds`和`status`。kind首批为`project_manifest`、`directory`、`workspace`、`package`、`source_module`、`declaration`、`call_candidate`、`algorithm`、`test_entry`。relatedRecords使用显式`relation`与`recordId`，不能引用不存在的记录；父/子关系来自来源组织，不能当作语义包含关系。
- 来源记录身份由规范来源键生成：scopeId、inputFingerprint、kind、项目相对规范路径、UTF-8字节区间（无字节定位时使用声明清单内键）和事实槽位的规范JSON摘要；不包含runId、时间、工具调用或请求ID。重复取得复用同一记录并追加证据，工具分歧保留为不同主张/诊断，不覆盖来源记录。acquisitionRuns单独标识取得运行，通过recordId/evidenceId关联；来源记录身份区别于实体注册身份；实体延续沿用持久注册表，不按名称/路径自动合并。v1的实体ref原样保留；没有独立来源记录时只从已有证据转换构造，不补造事实。
- 每条事实主张具有`origin`：`direct_source`、`derived_analysis`或仅用于旧档案兼容的`unclassified_legacy`；后者不得用于新解释构造。`derived_analysis`记录`premiseIds`与`method`。来源声明也不等于行为真实，支持/暂定/冲突状态仍独立。模型或规则解释不能伪装成来源直接陈述。
- 细粒度`acquisitionRuns`记录输入指纹、分析配置摘要、所选工具/版本、原始输出工件、执行/取消/失败状态；覆盖键为`inputFingerprint + configurationDigest + view + target + facets + conditions`。每项记录检查文件、排除/未处理文件、工具省略/截断及未解析原因。
- 单独的`sourceCoverage`和实体coverage避免把“全部语法文件解析成功”当作“全部实体/行为解释完成”。`complete`仅指所请求范围和事实类别，无全项目所有语义已穷尽的含义。
- 无映射的来源构造、工具输出及证据保留在来源记录中；映射状态未知不隐藏来源模块。E0–E4在有依据时可零个或多个，不由实体类型决定。

## 规范请求与接口

新增`skill/src/c2s_skill/fact_request.py`、`source_records.py`、`construction_plan.py`、`fact_query.py`。现有语言解析器、算法和存储模块按接口复用，避免新建第二套实体和证据类型。

`normalize_fact_request(value: dict | str) -> dict`产生：`profile`、`scopeId`、`view`（`source`/`entity`）、`target`（`kind`及可选`ref`、`path`、`name`）、`facets`、`detail`（`list`/`self`）、`expandDepth`（默认0）、`conditions`。输入不明确时返回`INVALID_REQUEST`/`AMBIGUOUS_TARGET`诊断而不猜目标。旧`functions`等选择器映射至source视图，旧entities请求映射至entity视图。

允许的facets是`organization`、`attributes`、`relations`、`implementation`、`algorithm`、`tests`。实体self详情隐含全部已取得自身属性及其缺口；不因expandDepth=0省略属性。展开深度最多8，循环以引用和诊断终止，不返回重复嵌套子图。按名称发现多候选时返回候选引用，不自行挑选。

`collect_source_records(root: Path, scan: ProjectScan, request: dict) -> dict`返回来源记录、证据、诊断和sourceCoverage。嵌套项目先盘点清单定位，再由各自原生声明及边界证据关联；无manifest仍返回来源目录/模块，不能制造Project所有权。

`plan_fact_request(request: dict, available: dict, inventory: list[dict]) -> dict`返回`needs`、`selectedTools`、`sourcePaths`和`stopReasons`。每项need包含目标、facets、前置need和取得理由。只建立解析/定位所必需的索引；列表枚举允许全声明扫描，但不连带全仓算法或语义候选构造。新参数`scan_project(..., source_paths: frozenset[str] | None = None)`中None表示显式全源扫描，非None仅处理该集合，仍保留完整inventory供缺口判断。

`execute_fact_query(root: Path, request: dict, store, *, tool_runner=None) -> dict`依次执行：校验固定输入→读适用覆盖→计划缺口→工具执行与解析→按需构造→契约校验→原子写入并读回→投影。可注入tool_runner仅用于后端和公开测试，不引入默认LLM；无法取得的解释保留缺口。

结果包含`profile`、`request`、`items`、`sourceRecords`、`claims`、`evidence`、`coverage`、`diagnostics`、`persistence`和`cost`。items中引用的实体和来源记录必须闭合；算法/伪代码作为implementation工件返回并保留步骤证据。JSON和Markdown从同一结果生成。

## 持久化、复用与故障

`SemanticEntityStore.read_request(scope_id: str, request: dict, input_fingerprint: str, configuration_digest: str) -> dict`返回可复用的目标描述、覆盖、缺项和所需引用闭包，不要求all-entities标记。

`commit_request(operation_id: str, document: dict, request: dict) -> dict`在同一SQLite事务中注册身份、校验全部引用、合并事实/证据、写覆盖及回执。同operation_id同内容幂等，不同内容拒绝。v2独立表保存，v1表不改写；同scope请求的合并采用BEGIN IMMEDIATE内读最新generation，禁止在事务外读旧包后覆盖并发补证。取消或工具失败只提交已完成且可验证片段和诊断，不能将未完成need覆盖标完整。

存储读取失败：保留读取诊断，允许按请求重取；保存失败：返回取得事实、persistence.failed及原因，不声称已持久化。工具成功但截断/路径异常/索引过期：仅记录候选和缺口，不发布完整覆盖。每次分析会话绑定固定输入指纹，复用时检查当前输入；发生变化终止本会话并报告INPUT_CHANGED，不静默混合快照。

## 查询缓存隔离

保留`QueryResultCache`，增加v2专用缓存键：请求profile、结果profile、规范请求JSON摘要、inputFingerprint及configurationDigest；不以源选择器字符串单独判同，不包含runId。缓存只保存统一结果，Markdown/JSON在读取后投影；命中仍需验证覆盖适用性。现有v1缓存条目不导入v2命名空间，升级时不得命中，允许保留供旧入口读取；默认版本切换使键版本自然变化。损坏、旧Schema或输入/配置不匹配时返回miss和诊断，按请求补取；不把读取失败当不存在。

## 兼容切换与回滚

先以显式`--model-profile semantic-entity-model-2`运行隔离档案；未指定时维持当前v1行为。v1导入保留全部实体标识、证据和原始payload；无法补齐的新来源/推导字段使用unclassified_legacy，并带legacyPayloadArtifactId指向原始载荷及UNCLASSIFIED_LEGACY诊断，不填成已验证；该记录不能满足当前请求所需的直接/推导来源覆盖，需补取后产生新有分类主张并保留原记录。导出v1时无法表达的sourceRecords与细粒度覆盖通过显式loss诊断披露，并保留v2原档案。

完成固定真实项目、查询/往返、故障、兼容及成本对照后才能把v2设为默认；切换前用SQLite备份API创建可回读备份。只保留v2新写入，v1旧档案与M1可读/独立接口保留。回滚恢复旧版本和备份，保留v2产物供排查，禁止将其反向覆盖v1。是否进一步删除兼容模块不在本轮决定范围。

## 质量、成本与验收

使用固定Click `2247b35ea1c47c727d7a06e51fa280e12a863ff6`、regex `94ac45b2a6e7b1c30927feb5b66c5ded5b7ad447`，隔离副本分析并核对源树未变。来源文件/声明枚举以原生清单和静态解析对照；语义解释按明确规则和逐项证据验证，不能用另一图工具的全部输出当真值。

每项任务包含公开正反测试与文档。最终集成遍历全部已发布实体、来源记录、关系、主张、证据、算法及缺口：契约合法、引用闭合、原始跨度可读回、来源查询与仓库查询一致。失败、歧义、无模块映射、动态/宏未解析、同名实体、截断、输入变化、并发补证和保存失败必须覆盖。

成本按相同项目、请求、输入及结果/缺口比较冷/热查询、解析文件数、算法函数数、工具索引、数据库体量、耗时及实际模型词元。没有调用LLM时记录未使用，不宣称词元节省。未测平台/target明确未测，不新增数值SLO。
