# codesemantics 首版 Skill 分发设计

## 目标与授权

按用户要求将产出物统一命名为codesemantics，作为可独立使用的首版成果撰写，去除产出中的DDD及沿革叙述，提供多个助手可部署的标准Skill及安装程序。用户已明确持续实施、不重复索批及main直接提交；本次继续原生执行，不重开设计批准问题。

## 方案与取舍

采用单份规范运行源码改名、白名单构建自包含Agent Skills目录、标准库Python安装程序。仅改说明而保留包名会留下可执行入口错名；复制一份运行源码另行维护会形成双轨，因此均不采用。开发规格、会话导入原件、上游工具与审核档案不进入分发包，也不为清理发布说明而篡改它们。

产品版本为0.1.0；协议版本字段仍按当前真实契约提供，不将内部格式编号写成发布沿革。生产Python命名空间改为codesemantics与codesemantics_contract，CLI名称codesemantics，产出文件内不保留品牌别名。保留SQLite数据保护与带证据/缺口的真实能力，不扩大到运行时等价或额外语言支持。

## 产出结构与安装

构建产物codesemantics/含SKILL.md、中文README/使用说明、LICENSE、manifest.json、install.py、scripts/命令包装及runtime/下的程序与必要契约。按白名单打包，不含测试、开发规范、会话报告、缓存、凭证或第三方源码。校验器直接使用当前公开模型契约，不为运行共享校验而携带已不使用的契约。manifest记录文件摘要；其校验用于完整性，不冒充发行签名。

安装程序可从仓库或本地zip运行，支持明确目标目录和有依据的助手目录预设、用户/项目作用域；未核实的助手目录要求--target明确指定，不静默猜测或映射到其他品牌。先验证路径、文件清单、摘要与链接类型；已有目录默认拒绝覆盖，显式替换也须确认目录是本产品所管理，并可失败回滚。安装到临时目标验证，不改当前宿主真实助手配置。

默认准备独立Python环境并安装最小依赖，支持--no-runtime先做离线文件部署。选择正式Python3.12，可使用--python明确指定；没有对应运行时而存在uv时允许按安装命令准备，不让查询阶段联网安装。命令包装从自身位置找runtime与.venv，可在任意工作目录执行。输出/数据库仍要求在分析输入外。

## Skill内容与助手兼容

SKILL.md采用name/description标准发现头，正文只载核心使用规则与一条可执行入口，细节链接到说明。没有其他强制项目分析Skill依赖。参考Codex、CodeArts、AtomCode、Qcode的公开资料，分别记录目录依据、部署能力与真实助手启动验证的界限。相似名称不擅自等同。

## 验证

先观察缺失安装器/发现清单/隔离入口的失败，再完成命名、构建、安装测试。验证分发内容无禁用品牌/DDD/沿革文本；包独立于仓库可导入；zip路径逃逸/符号链接/损坏摘要/覆盖与失败回滚；项目及用户目录；离线部署与实际独立环境安装；Python/Rust/图导入与缺Cargo行为；完整测试、固定项目事实回读、严格规格及原件摘要。最终一次新上下文只读审核，实质问题以RED→GREEN闭环。没有真实运行助手的场景只报告文件部署测试，不冒称端到端助手集成通过。
