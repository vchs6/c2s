# 移除V1公开接口设计

依据：用户2026-11-09明确要求“不保留V1接口”及独立代码审核，替代此前兼容保留决定；既有连续实施及main交付授权继续有效，不重复请求同一批准。

唯一公开运行协议为semantic-entity-model-2、semantic-fact-request-2、semantic-fact-result-2。删除旧CLI分支、旧结果缓存方法/别名、旧实体/完整事实/M1运行仓储、旧查询结果投影和导入导出接口；旧命令参数选择V1必须明确拒绝，不提供私有别名绕过。固定中文/源码选择器仍可规范化为V2，它们不是旧结果协议。

历史Schema、既有报告及导入原件保留追溯，不提供兼容服务。通用算法schema的1.0版本不是实体V1接口。V2共用结构校验提取为内部函数，公开校验器只接受V2。纯历史契约回归使用测试侧冻结辅助代码，不随产品提供旧接口。废弃运行接口的测试退休并列明，当前行为由V2正反、故障、并发、算法及真实项目遍历覆盖，不能把测试数减少说成覆盖提升。

不删除用户档案，不自动迁移或反写旧表；纯旧档案明确拒绝，混合档案只访问V2。保留显式SQLite完整备份工具，取消自动V1备份/转换/回滚接口。通过Git及独立备份恢复历史版本属于运维操作，不是产品兼容接口。

方案：直接移除公开旧运行代码，保留V2和必要内部校验。仅隐藏CLI会留下可调用API；将旧运行代码改名藏入私有模块仍保留兼容负担，因此均不采用。此为用户明确选定的删除方向，不再次讨论是否保留V1。

唯一任务在现有OpenSpec变更第11节。先测试公开接口缺失、拒绝旧profile、纯旧档案拒绝/字节不变、V2冷/热查询和备份；再实现；最后无历史上下文独立审核整个最终产品，而非只检查删除diff。修复实质问题后重跑全套和固定Click/regex验证。共享工作区代码审核不称私有盲验收。
