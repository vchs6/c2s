# AI代理治理与工作纪律

当前授权见ADR-0009：先完成准备，门禁通过后连续开发；不要逐项重复问同一批准。实际环境/权限阻塞和重大领域修订仍明确报告，不以自主权掩盖失败。

## 角色和证据

编码、代码审核、用例编写、测试执行、最终验证独立上下文、有效权限及输出所有权；协调者分配和汇总，不兼任所有角色自证。编码者不编写或读取独立suite、期望、原始私有日志；测试作者依据冻结公开契约和真实来源，不以candidate实现作期望；执行者不改代码/用例；验证者不改原始证据或豁免失败。

候选进程不能读harness/suite、其凭据或私有存储；编码身份不能经历史、日志、制品或管理API间接取回。分目录、worktree、同账号全权工具和只读提示不构成强制隔离。当前共享原生角色工具检查失败，不能承载真实盲编写；托管CI受限worker已有通过证据，实际模型工具绑定和交接仍需验证。

交接绑定公开契约、任务、candidate、suite、真实源、工具/host/target和运行证据版本；变化使相关结论失效。仅向编码者返回公开条款及必要受控缺陷信息，多轮反馈也不能逐步泄露suite。

## 双向独立与确定性执行（ADR-0010，当前规则）

五种职责不等于五方全部互盲。编码与独立验收作者必须双向不可见；审核可读实现，执行/验证可读必要工件，彼此不能越权改写。测试作者可读作为输入的真实项目源码，但不能读c2s候选实现或实现者讨论。独立作者拥有验收用例；编码可编写开发侧单元测试，但不能以此替代独立验收，也不能读取独立验收用例。

固定安装、构建、测试、摘要/版本核查默认无模型调用；需要判断的设计、编写、审核、失败诊断使用适用AI/人工角色。CI宿主属于可信执行面，模型和候选不得获得宿主shell或管理凭据。按任务授权所需输入，不再强求所有五角色互相无法读取。

## 方法与纪律

先读取相关领域/约束/任务及适用Skill；实际执行OpenSpec status/instructions，不能把Skill名当CLI命令。brainstorming处理未决设计，writing-plans维护唯一tasks，执行按原任务，verification-before-completion要求先有实际证据再声明通过。按用户要求将默认编码者写测试改成独立作者/执行者red-green；不得伪造失败或用基础设施错误证明业务red。

实质领域争议遵循battle-protocol.md；首轮独立、交叉质询、新reviewer，不能模拟角色或以共识代替用户确认。小技术细节在委托内决定并说明理由，不将所有选择推回用户。

不泄漏认证、模型凭据及私有工件；不修改导入原件/上游Skill伪造历史。失败报告实际命令、状态、影响及可恢复位置。任务未通过不勾完成，结构校验不冒语义/产品验收。

## 按任务选择模型

用户本次提出按任务类型选择合适模型；采用此执行策略，不统一固定模型。下表为当前代理技术配置，可随可用性和实测调整，不成为领域规格或产品后端承诺。

| 任务 | 当前选择原则/本轮实际配置 |
| --- | --- |
| 语法/格式/摘要/确定性检查 | 优先脚本/CLI，避免为可确定工作调用模型 |
| 规格清楚的局部实现、机械修改 | gpt-6.1-sol，通常medium；难度低且实际质量足够时可选更轻模型 |
| 跨文件集成、定位与修复 | gpt-6.1-sol high；失败按证据升级，避免反复低效尝试 |
| 架构/DDD边界/跨模块契约设计 | 选择更强推理模型；复杂审查本轮用gpt-6-astra high |
| 代码、安全、最终证据审查 | 按风险选择；普通小补丁可用sol，关键权限/跨模块结论用astra；保持独立身份/上下文 |
| 独立用例编写 | 依据契约及真实来源选模型，不读candidate生成期望；不同模型不代替访问隔离 |

分派时显式记录taskType、角色、modelRequested及reasoningEffort，避免无意继承昂贵模型；可取得时登记modelReturned、usage、耗时与重试，未知Token为unknown/null不填0。以验收质量为先，再比较总Token/时间及失败重试成本；失败须定位原因，不仅因为贵就静默降级关键审核。可用性变化时在既有授权/预算内选有足够能力的替代并记录，无法满足任务约束则blocked，不省略审核或测试。

本规则管理开发代理；产品语义事实提取仍按其工具/Skill/必要模型路径设计。API短健康检查的固定模型仅验证该模型/凭据在该次请求可用，不锁定所有任务，也不证明其他模型均可调用。

## 按任务选用专用Skill及使用回报

用户授权代理自行决定使用适合任务的专用Skill，例如调研任务使用适用的调研Skill；需要时在既有安装授权内安装/自检，不因工具名与关键词相关就启用。先按任务匹配已安装能力，读取其SKILL.md并遵循流程；来源不明、权限/成本不适用或仅有演示用途的Skill不能冒充通用研究工具。没有合适Skill时使用直接工具并如实说明，不为了凑数量重做已完成工作。安装/创建Skill时使用skill-creator及适用writing-skills流程，依赖/来源/版本/自检与副作用写最终Skill README。

每次工作结果报告实际使用的Skill名称（及可用来源/版本）、对应任务、产出/证据路径及验证结果。候选调研/仅安装/读取说明/实际执行分别记录，不能将第三方包附带Skill文件或工具CLI调用记成已完成Skill执行。专业Skill的输出仍需受领域契约、确认依据和独立验收约束；Skill共识不替代用户确认。

## 模型访问频率与额度分类

用户要求遇到限流控制访问频率。后续模型协调器默认单个在途请求，按凭据所属组织/模型记录共享限额，模型路由不用于绕过限额。临时rate_limit_exceeded/slow_down才做有上限的指数退避及抖动，优先尊重Retry-After；等待超过剩余任务时限则记录可恢复状态，不提前重试。credit_balance_exhausted、组织/项目消费上限、身份/权限拒绝均暂停相应路径，不用降频或换模型掩盖。当前健康检查刻意每次只发一次、无自动重试；上述协调器策略是实现约束，不能说已存在完整调度实现。

API余额不是所有开发方式的前置。Codex支持ChatGPT订阅认证；若改用该路径，仍须实际部署受信角色入口/安全登录维护及隔离交接，不能从当前会话登录推导私有CI已认证。计量必须标明执行入口及计费/配额来源，不将订阅限额与API余额混记。
