# AI代理治理与工作纪律

当前授权见ADR-0009：先完成准备，门禁通过后连续开发；不要逐项重复问同一批准。实际环境/权限阻塞和重大领域修订仍明确报告，不以自主权掩盖失败。

## 角色和证据

编码、代码审核、用例编写、测试执行、最终验证独立上下文、有效权限及输出所有权；协调者分配和汇总，不兼任所有角色自证。编码者不编写或读取独立suite、期望、原始私有日志；测试作者依据冻结公开契约和真实来源，不以candidate实现作期望；执行者不改代码/用例；验证者不改原始证据或豁免失败。

候选进程不能读harness/suite、其凭据或私有存储；编码身份不能经历史、日志、制品或管理API间接取回。分目录、worktree、同账号全权工具和只读提示不构成强制隔离。当前本地检查失败，隐藏测试及依赖流水线保持blocked。

交接绑定公开契约、任务、candidate、suite、真实源、工具/host/target和运行证据版本；变化使相关结论失效。仅向编码者返回公开条款及必要受控缺陷信息，多轮反馈也不能逐步泄露suite。

## 方法与纪律

先读取相关领域/约束/任务及适用Skill；实际执行OpenSpec status/instructions，不能把Skill名当CLI命令。brainstorming处理未决设计，writing-plans维护唯一tasks，执行按原任务，verification-before-completion要求先有实际证据再声明通过。按用户要求将默认编码者写测试改成独立作者/执行者red-green；不得伪造失败或用基础设施错误证明业务red。

实质领域争议遵循battle-protocol.md；首轮独立、交叉质询、新reviewer，不能模拟角色或以共识代替用户确认。小技术细节在委托内决定并说明理由，不将所有选择推回用户。

不泄漏认证、模型凭据及私有工件；不修改导入原件/上游Skill伪造历史。失败报告实际命令、状态、影响及可恢复位置。任务未通过不勾完成，结构校验不冒语义/产品验收。
