# 持续规划模式与统一开发门禁

状态：用户已授权此工作方式；Issue只登记议题，不自动触发。语义事实提取Skill产品开发关闭，本次维护工作流修正是用户明确授权的工具例外。

## 启动和推进

首次由用户在会话指定目标/Issue或维护者手动启动单项plan；不因Issue/评论/标签/定时自动开始。启动后，主代理在既定授权内维护议题/依赖、继续可推进工作；阻塞问题形成决策请求，其他无依赖议题继续。Runner只执行指定单项，不声称跨Issue无人值守。

规划顺序：总计划与边界 → 工作负载、质量目标和支持范围 → 总体架构及组件契约 → 查询契约 → 延迟构造 → 增量持久化 → 获取工具与语言/平台适配 → 并发/一致性/恢复/观测 → 整体审查。依赖允许并行研究，不能让未确认上游被当成已实现输入。既有Issue #3与A方案复用，不再建重复模型。

## 方法和工件

先实际brainstorming，核对需求及已确认约束，再对重大领域选择运行真实独立Battle，记录证据/异议/未决项；独立审阅不能代替用户裁决。实际获取OpenSpec status/instructions，复用相关active change，形成proposal、Requirement/Scenario、design及足够明确时的tasks。唯一实施计划是相应OpenSpec tasks，不维护两套清单。规划校验不等于产品测试。

主代理可以在授权范围内裁定有证据的技术细节，并标为delegated-agent-decision；不得写成用户明确确认。改变确认行为、扩大范围、重要成本/性能承诺、无法以证据裁决的架构取舍必须提出具体decision-request：问题、备选、推荐、证据、影响、所阻塞工件。候选或未决要求不自动升为正式基线；已有用户确认或授权范围内已裁决的要求，经过独立审核和严格校验后可形成相应规格，必须保留决策权限及依据。

## 功能、质量与支持范围

每个能力同时核对功能及非功能：查询性能（已有事实/首次构造、首个结果/完整结果、延迟分布、并发/吞吐）、构造成本（工具耗时/Token/内存/重复工作）、存储效率、正确性/一致性、扩展性、可观测和可维护性。指标记录适用负载、规模、冷/热状态、平台/环境、计量边界、候选目标/预算、验证方法及取舍；无依据不填硬性毫秒值，不用规划讨论冒充已跑基准。

跨语言/跨平台为全局要求，至少分开：

| 维度 | 规划要明确的边界 |
| --- | --- |
| 源代码语言 | 首期支持语言/版本、混合语言、跨语言引用/调用边界、语言差异及未知语义；不等同已实现所有语言 |
| Skill运行平台 | 候选Windows/Linux/macOS/WSL/容器/远程环境的支持级别、工具可用性及依赖，不预先承诺全部支持 |
| 被分析项目目标平台 | OS/CPU/ABI/工具链及条件编译对语义、身份/上下文和构建解析的影响；host和target分开 |
| 可移植性与验证 | 路径/大小写/编码/行尾/链接、文件系统及进程权限差异；支持矩阵、证据、未支持/降级行为与候选验收环境 |

矩阵各单元区分目标支持、候选、已验证、未验证、不支持；没有实际运行证据不得写已验证。查询延迟/构造预算不能跨平台直接外推；工具缺失或只支持某语言/平台时明确能力缺口。平台与语言覆盖范围中重要资源取舍由用户裁决。

## 三个不同门槛

1. 单项方案确认：如Issue #3选择A，只确认方案，不开始产品开发。
2. 整体规划审核：检查全部功能、非功能、跨语言/跨平台、依赖、共享契约、待决事项与验收矩阵；通过后冻结规划集合。
3. 产品实施批准：用户明确批准冻结集合及实施范围，才允许开发；当前Runner没有此入口。若未来需要实施工具，另行授权修改，不能拿旧单Issueapprove令牌代替。

规划期间不写产品代码/Schema/目录/存储/获取器/产品测试实现，不安装产品依赖，不自动归档。语句级算法粒度和事实数量膨胀专项讨论按用户要求暂缓；表达能力不是逐语句事实化承诺。

## 当前动作的边界

本次只修正工作方式并创建规划Issue，不自动开始这些议题，不运行真实模型或性能基准，不声称已实现完整规划平台。合格工件直接提交main；首次规划启动由用户明确指定。议题创建后只登记依赖/交付/验收，不自动给方案贴已批准标记。

## Token消耗控制（用户明确目标）

Token控制同时约束规划过程与未来Skill运行：按议题/阶段/查询分别统计输入、输出、上下文重复加载、模型/代理调用及重试；工具可确定取得的信息优先确定性提取，避免代理反复通读同一材料。Battle按实质争议触发，证据引用和增量上下文优先，不为每个机械性编辑重复开展；不以减少Token为由跳过必要独立审查或丢弃语义证据。未来查询比较冷/热、首次构造/复用、增量更新和跨语言/跨平台差异，提出每查询/任务预算、调用上限及超限的显式中止或人工决策策略。具体预算数值由场景和证据讨论，未测量不声称节省比例；准确性、性能和Token成本的重大取舍提交用户裁决。
