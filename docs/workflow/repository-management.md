# 仓库管理

合格授权工件可直接提交main，不自动建PR/分支或归档。推送前核对基点、补丁范围、严格OpenSpec及适用检查；拒绝force和过期基点覆盖，发布后读回。并行准备仅读或分明确文件所有权，主协调者统一集成，产品编码与测试所有权不混。

正式规格openspec/specs，活动变更openspec/changes，领域docs/domain，决策docs/decisions，过程证据docs/development/reviews。历史草案/原件留存，当前决定通过新ADR及明确接续维护；不篡改原件制造旧稿已更新的假象。

不提交node_modules、.local环境/克隆/索引、认证、原始私有suite或日志、宿主配置及运行会话数据。依赖记录版本与来源，工具包/契约版本和产品0.b.c区分；未实际发行不创建产品tag或宣称发布。

既有CI在push/PR做公开确定性校验，不自动运行开发模型；Issue仅登记，当前维护Runner仍仅plan/smoke。产品编排、角色私有权限及外部验收设施必须实际部署验证，不能因有GitHub写权限就宣称具备。分支保护等远程设置未核验，不当作已启用保障。

集合manifest维护文档/契约摘要，排除自身、执行报告及发布回执避免自引用；摘要只证明版本变化，不证明语义正确。代码/suite/环境变更应使对应审核/运行/验证结论重新关联或失效。
