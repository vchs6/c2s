# 任务分解与完成规则

唯一实施待办在各OpenSpec变更tasks.md；里程碑、需求矩阵和readiness只作索引/状态，不复制产品任务。Skill计划引用原任务，子代理brief按任务读取，不灌整段会话。

每项任务须包含：稳定ID、上游Requirement及决定、依赖、负责角色、精确输入/输出契约、交付路径、可修改范围、验证方法、通过/失败条件。未确定的接口不能通过“合理实现”“适当测试”假装已可执行。

粒度以能独立审查和拒绝的交付为边界；一个业务不默认就是一个任务。跨多个里程碑的任务应在原tasks中拆稳定子ID，保留父依据；完成切片不能勾整个父任务。候选试验和产品实现分开，公开探索不冒隐藏验收。

独立作者/runner先取得真实失败证据，编码者实现，代码审核和最终验证独立执行；任务自身携带需要的测试/说明，不积压到最后统一补。复用既有产品路径/公共契约，禁止每个适配器再建一套类型。

完成需对应实际版本和命令证据，失败/blocked保未完成；纯文件存在、OpenSpec done、代理自述不能作产品完成。授权内依赖就绪后持续下一项；失败只重验受影响范围，不无理由重复全部讨论或检查。
