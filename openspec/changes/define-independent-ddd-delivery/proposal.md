# Proposal

当前执行接续：ADR-0009已授权必要环境准备及门禁通过后的连续开发；下文“仅规划/实施另批”为原阶段记录，不撤销该授权。2026-11-03用户要求按原生子代理、独立测试环境及runner直接隔离候选的平级方案尝试准备；不要求嵌套Codex或Docker作为所有工作前提。本轮准备涵盖公开环境自检、维护CI接入，以及用户明确要求的主代理固定SHA白名单同步角色独立仓库的公开搭建/访问边界实验，以及用户选择的CI角色仓库边界实测，沿用本change唯一tasks，不修改正式语义规格、不创建隐藏suite、不放行未验证门禁。

当前模式澄清（ADR-0010）：双向独立编写是必需信息边界，五种职责按需读取；固定CI执行不必调用模型。本次包含公开双向边界/版本交接准备工具及实际运行验证，不实施语义提取产品；早期仅规划/无CI描述属于历史范围。

## Why

用户要求按里程碑持续交付，并使编码、代码审核、测试编写、测试执行、最终验证独立。现有任务中的同角色写测试/实现流程与此不符，需要先固化交付约束及规划，不启动产品开发。

## What Changes

- 将用户明确的五角色独立、真实项目验收、测试对编码者不可见、显式授权后连续推进及0.b.c版本约束固化为主规格；依据ADR-0008。
- 在design.md比较隔离方案、定义交接与证据失效规则；当前共享文件系统无法证明隔离，隐藏测试编写及执行保持blocked。
- 形成M0–M4里程碑索引，复用#3、#5–#12唯一tasks；将旧同角色测试步骤修订为独立角色交接，不创建第二套产品计划。
- 明确功能里程碑增b、修复增c的发布设计；0.1.0仅为首次产品版本候选，本轮不修改工具包版本、契约版本、标签或发布。

## Capabilities

### New Capabilities

- `independent-delivery`: 五角色独立、基于真实项目的隐藏验收、授权内连续推进及证据门禁。
- `product-versioning`: 当前产品版本采用0.b.c，仅递增b/c，发布版本与验收证据对应。

### Modified Capabilities

无。既有语义需求和模型A不重开；交付约束不改变查询行为。

## Impact

仅规划、规格、决策、仓库协作规则及证据索引。关联Issue #4、#13和既有子变更tasks，不新建重复Issue。无产品代码、实际用例、CI、凭据、依赖或上游Skill修改；无apply或archive。当前确认只授权本轮规划，整体技术设计仍未冻结，产品实施另行批准。

## ADR-0013 当前约束（2026-11-08）

保留独立审核、真实项目验收与授权推进；DDD不再是交付契约依据。目录名作为历史标识保留，不要求产品采用DDD。隔离例外继续依据ADR-0011。 依据：`docs/decisions/0013-非DDD语义事实模型.md`。历史执行记录中的DDD或旧模型表述不构成现行约束。本轮只进行文档修订，产品重构完成状态不变。
