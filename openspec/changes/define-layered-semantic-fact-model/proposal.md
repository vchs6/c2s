# Proposal

## Why

ADR-0001已确认五层组织方向，用户也已确认查询响应的最小范围，但仓库此前只有候选delta与规划，没有正式规格基线。本轮按用户明确授权，将已确认内容与未批准候选分开，形成可追溯、可验证的约束。

## What Changes

- 以ADR-0002逐项记录确认依据，区分用户确认、候选方案与代理建议；不把Battle共识视为批准。
- 在`semantic-fact-model`固化五层名称与组织尺度、非强制包含/细化、单一主体身份及跨层类型引用。
- 在`semantic-fact-query`固化按请求响应、默认顶层最小事实集、明确要求才展开，以及未展开与获取状态的区别。
- 选择性同步上述已确认内容到主规格。候选事实模型细节保留在讨论记录，算法delta保留为未批准候选，不同步。
- 实现选择保留在design.md，待决问题在讨论记录；tasks.md记录本轮规格任务和仍受批准门槛约束的未来任务。

## Capabilities

### New Capabilities

本变更起点无主产品规格，以下能力由本变更引入；前两项本轮提前同步确认部分，尚未实现，不因同步后存在而另建重复能力。

- `semantic-fact-model`：五层语义组织与跨层主体关联的确认基线；字段/谓词/完整公共模型仍是候选。
- `semantic-fact-query`：查询最小响应及显式展开的确认基线；完整请求/结果契约和执行流程不在本轮实现。
- `algorithm-description`：操作契约、结构化算法与伪代码投影的候选能力；现有delta仅供后续评审，本轮不进入主规格。

### Modified Capabilities

无本变更之前已存在的产品能力。本轮没有修改其他活动变更的规格或工作流行为。

## Impact

仅修改正式规格、当前模型变更的必要规划，以及确认/讨论/验证记录和资料索引。不实现Skill、获取器、存储服务、机器可读目录、Schema、校验器或产品测试，不修改Issue状态或自动工作配置，不自动归档。

未来公共契约任务的路径和格式仍为design.md中的建议，待相关行为与方案确认后才能执行；本轮正式基线约束该讨论，不能因未实现重开已确认需求。依据见`docs/decisions/0002-confirmed-specification-baseline.md`。
