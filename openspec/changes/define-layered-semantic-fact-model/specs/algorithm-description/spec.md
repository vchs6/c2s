# Spec Delta

## Purpose

为操作的可观察行为和实现算法提供语言无关且保持来源语义的描述能力，使下游能够区分契约要求、源码解释与运行观测，读取有步骤对应和省略边界的伪代码，而不把摘要误认为完整展开或实现等价证明。

## ADDED Requirements

### Requirement: 操作契约独立表达

系统SHALL以E3契约表达操作或算法的输入域、前提、正常/错误/终止结果、状态与资源效果、外部交互及适用观察边界；协议、时间和并发约束MUST以类型化条件或关系表达。契约主张MUST携带模态与证据，SHALL NOT仅由签名、修饰符或E4实现关联推断成立。

#### Scenario: 只读访问形态不代表纯性
- **WHEN** Rust操作签名为`parse(&self)`且来源显示内部可变状态更新
- **THEN** 保留E2签名与E3状态效果，不把`&self`推断为无副作用

#### Scenario: 失败回调的返回结果
- **WHEN** C++ SAX严格结束检查调用接收器的parse_error并返回其结果
- **THEN** 契约保留接收器返回或抛出的行为边界，不把错误回调结果固定改写为false

### Requirement: 算法描述身份目的与实现关联

系统SHALL为AlgorithmDescription提供独立身份、描述目的、问题范围、输入输出、前后置/错误/效果、适用上下文、结构化body、实现引用、证据、抽象规则及省略项。规范算法、当前实现解释与抽象算法MUST可区分。管理归属与参与项目SHALL分开，算法MUST可关联多个项目的实现而不复制身份或伪造workspace。

#### Scenario: 跨项目协作算法
- **WHEN** 一个算法由两个独立项目的操作共同实现且没有自然管理项目
- **THEN** 保留一个算法及两个实现关联，显式记录归属未决，不要求创建项目或共同workspace

#### Scenario: 当前实现与规范算法同时存在
- **WHEN** 同一行为有规范性算法和有省略项的源码解释摘要
- **THEN** 两者保留不同描述目的、证据和关联，不互相覆盖或把implemented_by当等价证明

### Requirement: 结构化行为体与引用完整性

系统SHALL支持顺序、绑定、赋值、带类型计算、选择、循环、调用、返回、失败/异常处理、资源操作、并发/同步与UNKNOWN结构。每步骤MUST有算法域内唯一stepId，区域及控制/数据边MUST有类型且引用有效；控制转移MUST指明目标。未知条件、调用或子过程SHALL保留缺口，不能默认成功。

#### Scenario: 显式栈与嵌套循环
- **WHEN** 描述Rust访问器的外层遍历、内层退栈和回调错误传播
- **THEN** 区分两个循环区域、continue/break目标及回调失败出口，未展开的induct和pop保持引用与省略说明

#### Scenario: 无效步骤与未知调用
- **WHEN** 数据边引用不存在的stepId，或动态调用目标尚不能解析
- **THEN** 前者产生定位到算法和边的校验错误，后者产生UNKNOWN/候选目标及影响范围，不补造唯一目标

### Requirement: 求值错误资源与并发语义保持

系统SHALL显式表达影响行为的求值顺序、数值/类型规则、别名与状态位置、错误返回与异常的差异、资源生命周期及外部效果。并发SHALL保留偏序和同步约束，不能虚构唯一串行顺序。无法映射的语言语义MUST有类型化扩展或UNKNOWN及缺口，SHALL NOT静默降为普通顺序步骤。

#### Scenario: 异常与返回错误不同
- **WHEN** Rust问号传播、Python抛TypeError与C++接收器回调分别出现
- **THEN** 分别保留结果传播、异常转移和回调行为，不以统一无类型fail抹去可观察差别

#### Scenario: 数值和并发尚未确定
- **WHEN** 来源的溢出规则、求值次序或线程同步证据不足
- **THEN** 报告对应语义缺口，不能借伪代码默认数学整数、从左到右或单线程执行

### Requirement: 宏生成与注解的分阶段来源

系统SHALL区分变换定义、应用、输入、生成主体和多对多来源映射，以及元数据附着、解释阶段和已证处理效果。仅有宏调用或注解文本时SHALL NOT声称展开/执行结果已获得；重复展开生成的主体MUST可区分。语言条件属性、静态注解处理与运行时装饰器SHALL NOT仅凭表面语法合并。

#### Scenario: 宏未展开与重复展开
- **WHEN** 只读取`vec![]`应用，或同一宏在不同上下文生成多个局部绑定
- **THEN** 前者记录应用及展开缺口而不伪造AST；后者按应用与上下文区分生成绑定并映射来源

#### Scenario: 元数据与运行时装饰器
- **WHEN** 读取Rust cfg属性、未支持的Java注解处理或Click command装饰器
- **THEN** 分别保留条件、处理阶段缺口或运行调用/对象替换事实，不把三者都解释成无行为的附着标记

### Requirement: 匿名操作闭包与绑定语义

系统SHALL区分匿名操作定义、可调用值/实例、捕获对象或位置、捕获方式和生命周期，并保留let等绑定引入、初始化、模式、作用域、可变性与路径可用条件。绑定SHALL NOT等同赋值；原函数、包装函数和返回的命令对象MUST保持可区分身份。

#### Scenario: 闭包捕获与条件绑定
- **WHEN** lambda捕获外部绑定或let/if let引入多个有路径条件的绑定
- **THEN** 记录捕获位置与方式或明确未知，分别表达初始化、作用域和路径可用性，不按匿名名称合并主体

#### Scenario: Click装饰器替换返回值
- **WHEN** 装饰器把函数包装成Command且保存callback引用
- **THEN** 保留装饰器调用、Command构造、返回替换、callback及名称绑定，不把Command当原函数本体

### Requirement: 伪代码是可追溯投影

系统SHALL从结构化body生成具有步骤对应、适用上下文和省略标记的可读伪代码。投影MUST保留分支、循环、失败和效果的可观察差别，引用未展开子过程并标记UNKNOWN；有省略或未验证语义时SHALL NOT声称完整项目算法或与实现等价。投影更改SHALL可追溯到body而不建立互相漂移的第二套算法事实。

#### Scenario: Python位置参数分配的零规格
- **WHEN** 投影Click参数分配算法处理规格n等于0、负通配及多个通配
- **THEN** n等于0只消费规格而不消费实参、不追加结果；负通配保留余项和尾段逆序，第二个通配抛TypeError

#### Scenario: 摘要保留边界
- **WHEN** 输出Rust遍历、C++ SAX入口或Python位置参数分配的选定区域摘要
- **THEN** 对应到固定来源及步骤并列出未展开子过程，不把读取测试断言说成测试已运行，也不把局部算法说成整个项目完整语义
