# Semantic Analysis Quality

## Purpose

为分层语义事实提取建立可重复、质量约束下的性能与成本评价口径，显式限定负载、支持组合和证据范围，防止以不完整结果或未经测量推断产品收益。

## ADDED Requirements

### Requirement: 可复现评价档案
系统 SHALL 将评价绑定输入快照、请求范围、规模、并发、变化形态、工具模型版本、源语言含混合边界、host和target；记录质量判据及支持组合证据，未知组合不得宣称支持。

#### Scenario: 混合组合尚无证据
- **WHEN** 单语言验证成功但某混合边界没有验证
- **THEN** 评价将该组合标为未验证而不从单语言结果外推支持

### Requirement: 全部请求与成功结果分别评价
系统 SHALL 将成功、部分、失败、超时和不支持纳入请求总体并分别报告；语义成功须满足请求所需语义和证据，首结果与语义完整成功分开，语义成功延迟附语义成功率；持久化结果和操作汇总独立统计，完整语义但保存失败为操作部分，不将两维合成单一成功。

#### Scenario: 快速缺口响应
- **WHEN** 查询很快返回缺口但未满足必要语义
- **THEN** 计入请求总体和部分或失败统计，不计为语义完整成功

### Requirement: 同质量Token与成本比较
系统 SHALL 在固定输入、语义范围、正确性、证据和平台条件下分别比较首次构造、复用、局部变化的全链路LLM输入输出Token、调用数、上下文量和重复分析量，并报告延迟、构造及存储成本；无测量不得宣称收益。

#### Scenario: 热复用没有模型调用
- **WHEN** 已有事实查询无需调用模型
- **THEN** 仅记录该复用场景成本，首次构造和来源变化成本仍独立测量且不能被推断为零

### Requirement: 端到端计时与资源归因
系统 SHALL 从接受请求计时至首个有效语义结果及请求终止，区分流式前缀和完整成功，将排队、核验、工具、模型、存储、投影及重试归入逻辑请求；报告样本数、延迟分布、完成与成功吞吐、峰值内存、工具耗时和存储占用/写放大。

#### Scenario: 首次失败后重试成功
- **WHEN** 一次逻辑请求发生工具失败后重试成功
- **THEN** 全链路延迟和成本包含失败尝试，单次尝试可另列但不重置逻辑计时或将前缀标作完整成功
