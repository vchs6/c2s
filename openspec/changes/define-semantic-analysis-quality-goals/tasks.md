## 独立交付约束（ADR-0008，优先于旧同角色步骤）

本清单所有测试步骤由独立用例作者编写、独立执行者运行，编码者只改实现与公开说明，不编写或读取测试；代码审核与最终验证另用独立身份。所有测试/fixture交付与测试命令均在交付变更2.2绑定的私有测试区，不落入编码可读产品仓库/历史/日志；本文既有名称与期望只是公开契约示例，不是隐藏suite。本轮未创建这些文件或运行产品测试。旧T/unittest直接同进程导入candidate不能用于隐藏验收，实际隔离runner命令须先绑定再执行。具体交接及红绿验证见`../define-independent-ddd-delivery/design.md` §2–4；里程碑仅索引本tasks，不复制产品任务。公共类型/路径及runner接口须先经交付2.1/2.2就绪检查；整体设计未冻结，实施另批，当前全部产品checkbox保持未完成。

## 1. 实际评价档案

- [ ] 1.1 依据“可复现评价档案 / 结果如实报告而不虚报严格正确性”，交付`skill/quality/profiles/`及`独立测试区/suites/product/quality/`。输入/输出：实际输入、请求范围、环境、取得项/缺口原因→评价档案。由独立作者先写契约/行为用例，独立执行者记录真实失败，编码者再实现，代码审核与最终验证分别独立进行。通过：覆盖指定目录非主src内容、无工具/解析失败、无实际负载数据场景；不要求先有语义金标，负载范围未定不阻塞记录方法；失败：失败不进总体、编造缺口原因、用测试fixture宣称普遍语义正确。依赖公共结果契约；档案类型由代理细化，不等待用户指定数值。

- [ ] 2.1 依据“优化前后Token与成本比较 / 性能与Token由优化前后对照评价”，交付`skill/quality/reports/`及`独立测试区/suites/product/quality/`。输入/输出：优化前后运行事件与同输入/请求档案→耗时/Token及取得内容/缺口差异。由独立作者先写契约/行为用例，独立执行者记录真实失败，编码者再实现，代码审核与最终验证分别独立进行。通过：首次/同次复用/后续补充/失败重试成本可核，实际Token输入输出、调用、上下文和资源齐备；漏取差异明确显示；失败：只挑成功尝试、只靠限额、用删必要事实或隐藏缺口当收益、未测宣称节省。#11只消费此口径；优化拆分实验可选，不要求三组全部跑完或先给硬SLO。
