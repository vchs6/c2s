**Goal:** 如实记录取得/缺口并比较优化前后性能与Token

**Architecture:** 一个测量口径服务全部阶段；报告不宣称严格语义正确。

**Tech Stack:** 具体产品类型/接口由代理在技术设计中落实；当前不创建产品Schema或代码。候选报告Markdown、结构数据JSON；自维护验证脚本遵守Python 3规则。

**Spec:** 本变更specs/design.md及ADR-0007；正式query/scope/lazy/quality主规格中仅明确确认项生效。

**Global Constraints:** 首期Rust/Python；指定目录全部内容为分析范围；单次项目不变；本次顶层取决用户请求，完整返回该范围并报告缺口，不递归夹带；负载实测后定；必要操作由设计选择；不以严格语义正确性金标为当前前置。

**Review Focus:** 主目录以外内容被漏掉；顶层被缩为任意最少字段；双输出事实/缺口漂移；同主体重复全量分析；把未取得或未实测说成完整/有收益。下列任务分别覆盖。

## 1. 实际评价档案

- [ ] 1.1 依据“可复现评价档案 / 结果如实报告而不虚报严格正确性”，交付`skill/quality/profiles/`及`独立测试区/suites/product/quality/`。输入/输出：实际输入、请求范围、环境、取得项/缺口原因→评价档案。由独立作者先写契约/行为用例，独立执行者记录真实失败，编码者再实现，代码审核与最终验证分别独立进行。通过：覆盖指定目录非主src内容、无工具/解析失败、无实际负载数据场景；不要求先有语义金标，负载范围未定不阻塞记录方法；失败：失败不进总体、编造缺口原因、用测试fixture宣称普遍语义正确。依赖公共结果契约；档案类型由代理细化，不等待用户指定数值。
