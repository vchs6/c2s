# Proposal

## Why

Issue #7：定义有界、可判歧义的规范请求及逐项结果契约。已确认约束沿用共享context与主规格，相关上游候选见upstream。新结论非用户确认；本Issue讨论与复核有可追溯记录。

## What Changes

- 增补规范请求、逐项覆盖和有界展开规则。
- 自然语言解释为候选入口，不要求每次调用模型。
- 复用模型A身份、状态维度和内嵌白名单。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `semantic-fact-query`: 增补公共请求/结果约束，不改既有四项要求。

## Impact

依赖Issue [3, 5, 6]。仅候选规格和规划，不生成产品代码/Schema/目录/存储/测试，不归档。ADR-0007已明确基本系统需求与评价/操作授权；具体契约/工具能力等由代理设计并诚实报告，不再等待用户给金标、硬SLO或逐工具批准；跨次更新不自动选择。

## 2026-11-02 系统需求确认接续

以ADR-0007及后续“当前一层=符合用户请求要求的顶层语义事实”为用户确认依据；需求与工具/接口等代理设计决定分开。人机双输出、缺口原因、查询触发与同主体补充、必要操作可执行及优化前后自评已明确。需求基线不等于全部设计已批准，当前仍不实施/归档。
