# Proposal

## Why

Issue #7：定义有界、可判歧义的规范请求及逐项结果契约。已确认约束沿用共享context与主规格，相关上游候选见upstream。新结论非用户确认；本Issue讨论与复核有可追溯记录。

## What Changes

- 增补规范请求、逐项覆盖和有界展开规则。
- 自然语言解释为候选入口，不要求每次调用模型。
- 复用语义实体身份、属性/关系、证据/覆盖状态和有界响应契约；源码构造作为实现视图。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `semantic-fact-query`: 以语义实体、属性、关系、实现映射和验证目标描述查询；原类/函数入口作为源码构造视图保留，E0–E4不确定查询主体分类。

## Impact

依赖Issue [3, 5, 6]。仅候选规格和规划，不生成产品代码/Schema/目录/存储/测试，不归档。ADR-0007已明确基本系统需求与评价/操作授权；具体契约/工具能力等由代理设计并诚实报告，不再等待用户给金标、硬SLO或逐工具批准；跨次更新不自动选择。

## 2026-11-02 系统需求确认接续

以ADR-0007及后续“当前一层=符合用户请求要求的顶层语义事实”为用户确认依据；需求与工具/接口等代理设计决定分开。人机双输出、缺口原因、查询触发与同主体补充、必要操作可执行及优化前后自评已明确。需求基线不等于全部设计已批准，当前仍不实施/归档。

## 领域模型对齐复核（2026-11-07）

领域模型对齐：项目、模块/能力、数据、计算、外部参与者和测试实体及其属性/关系是语义查询目标；类、字段、方法、函数、枚举等保留为源码构造查询视图，并通过有证映射连接实体。原类/函数示例描述定位实现的兼容视图，不再定义公共领域对象类别。

## ADR-0013 当前约束（2026-11-08）

实体详情一次返回自身已取得属性、直接关系及缺口，子实体按请求展开；源码类/函数查询是实现视图。算法及伪代码是带证据和局限的实现参考，不产生迁移建议。 依据：`docs/decisions/0013-非DDD语义事实模型.md`。历史执行记录中的DDD或旧模型表述不构成现行约束。本轮只进行文档修订，产品重构完成状态不变。
