# Tasks

> 实施时使用superpowers:executing-plans或subagent-driven-development，逐项引用本唯一tasks；当前不实施、不归档。用户系统需求已确认，技术契约/设计仍须收敛并整体审核后另取开发批准。

**Goal:** 按请求返回顶层完整事实及人机双输出

**Architecture:** 内部规范请求定位目标；统一结果控制顶层事实和缺口，再生成两种输出。

**Tech Stack:** 具体产品类型/接口由代理在技术设计中落实；当前不创建产品Schema或代码。候选报告Markdown、结构数据JSON；自维护验证脚本遵守Python 3规则。

**Spec:** 本变更specs/design.md及ADR-0007；正式query/scope/lazy/quality主规格中仅明确确认项生效。

**Global Constraints:** 首期Rust/Python；指定目录全部内容为分析范围；单次项目不变；本次顶层取决用户请求，完整返回该范围并报告缺口，不递归夹带；负载实测后定；必要操作由设计选择；不以严格语义正确性金标为当前前置。

**Review Focus:** 主目录以外内容被漏掉；顶层被缩为任意最少字段；双输出事实/缺口漂移；同主体重复全量分析；把未取得或未实测说成完整/有收益。下列任务分别覆盖。

## 独立交付约束（ADR-0008，优先于旧同角色步骤）

本清单所有测试步骤由独立用例作者编写、独立执行者运行，编码者只改实现与公开说明，不编写或读取测试；代码审核与最终验证另用独立身份。所有测试/fixture交付与测试命令均在交付变更2.2绑定的私有测试区，不落入编码可读产品仓库/历史/日志；本文既有名称与期望只是公开契约示例，不是隐藏suite。本轮未创建这些文件或运行产品测试。旧T/unittest直接同进程导入candidate不能用于隐藏验收，实际隔离runner命令须先绑定再执行。具体交接及红绿验证见`../define-independent-ddd-delivery/design.md` §2–4；里程碑仅索引本tasks，不复制产品任务。公共类型/路径及runner接口须先经交付2.1/2.2就绪检查；整体设计未冻结，实施另批，当前全部产品checkbox保持未完成。

## 1. 请求定位与目录范围

- [ ] 1.1 依据“规范请求不静默扩大 / 按请求查询项目类型成员与函数事实”，交付`skill/query/normalization/`及`独立测试区/suites/product/query/`。输入/输出：用户查询或Skill规范请求+指定目录→项目/主体/所需顶层范围。由独立作者先写契约/行为用例，独立执行者记录真实失败，编码者再实现，代码审核与最终验证分别独立进行。通过：项目类清单、类成员、成员定义、函数定义/实现四例可定位；嵌套/测试/示例不被默认排除；歧义如实报告；失败：只找主src、目录当唯一Project、同名任选或把顶层固定E编号。依赖#3身份/目录与#6端口；请求契约由代理落实。

## 2. 请求相对顶层投影

- [ ] 2.1 依据“默认顶层最小事实集 / 顶层结果不夹带递归内容”，交付`skill/query/projection/`及`独立测试区/suites/product/query/`。输入/输出：规范请求+实际取得事实/覆盖→单一公共结果与缺口原因。由独立作者先写契约/行为用例，独立执行者记录真实失败，编码者再实现，代码审核与最终验证分别独立进行。通过：范围内所需顶层事实不任意删减；图环、引用类型、证据不夹带递归定义；获取不到有原因；已取得未展开与不存在区分；失败：只返任意最少字段、为Token少取必要事实、多深度递归子图、空即不存在。#8提供取得结果，#12提供提交/取消状态；不实现工具获取。

## 3. 报告与结构数据同源

- [ ] 3.1 依据“同时提供可读报告与结构化数据 / 语义完成与持久化结果独立”，交付`skill/query/presentation/`及`独立测试区/suites/product/query/`。输入/输出：同一公共结果→Markdown报告及机器结构数据。由独立作者先写契约/行为用例，独立执行者记录真实失败，编码者再实现，代码审核与最终验证分别独立进行。通过：两种输出事实身份/范围/缺口原因一致；完整取得但保存失败仍列事实并明确未存；同次复用不重新分析两遍；失败：报告说完整而结构数据有缺口、来源丢失、单success吞持久化失败。具体编码由代理设计，复用公共契约；不另建事实模型。
