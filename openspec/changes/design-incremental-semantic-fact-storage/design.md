# Design

## Context

已确认：共享context、ADR-0001/0002和两份主规格；模型A由用户选择但未批准实施。当前无产品实现或性能实测。新设计是候选；细节由授权范围内代理提出，不成为用户确认。讨论、异议及独立复核见本Issue评审目录。

## Goals / Non-Goals

重复构造/重试不重复存储，变化不隐藏，保存原语义及证据。非目标：数据库实现、快照查询、全版本历史、自动重命名识别。

## Approaches

候选后端端口+确定性规范比较，支持原子发布语义。单文件原子替换实现简单但并发/大集合写放大；事务存储支持细粒度去重但增加依赖和平台成本；不可变分块清单有复用优势但需垃圾回收与引用校验。无负载证据不锁定后端，D01/D02冻结后比较；这些物理手段不能代用户决定D03。

## Decisions

复用#3主体身份与主张条件/模式；主体、主张、证据、覆盖分别比较，不用同名、路径、层号或源码摘要当主体身份。候选内容指纹仅加速规范化等价比较，需处理哈希碰撞并保留原始语义，不能作为跨语义身份。顺序有语义的参数/算法不能排序抹平；证据位置、条件和主张模式不能删除求同。

| 候选与已存比较 | 操作含义 |
| --- | --- |
| 同主体、相同规范主张和相同证据 | already-stored，不再写重复内容 |
| 主张相同，新增独立证据 | 只新增证据及关联，不复制主体/主张 |
| 同主体、不同适用条件/模式 | 按模型A可比较性校验后保存新增内容，不擅自覆盖 |
| 同适用条件且不兼容主张 | 冲突保留并标诊断，不最后写入者裁真 |
| 来源变化导致旧依据失效 | 输出changed/needs-policy；不能already-stored掩盖，也不自动upsert |

D03待裁决选项：A维护当前有效集合，允许对同身份来源变化进行显式失效和必要更新，重复内容不写；优点查询当前性直接，需批准更新语义与原子替换，来源核验观察可另存但不默认为历史服务。B严格新增，来源变化仅在本次核验响应中报告无效/待重建，不改原持久化记录；由用户显式授权重建当前集合；守字面不更新但查询可能长期缺口/重建昂贵。C追加每次变化记录需历史管理和回收，扩大服务范围，不建议默认选择。主代理建议A但这不是用户确认；现阶段只落实两者共用去重/状态契约，变化写任务阻塞，不用内容摘要伪造新主体绕开。

提交消费经公共校验候选、读取观察和期望有效性/内容基点，产出新增/已存/冲突/需政策/失败逐项结果。幂等标识绑定规范提交内容及政策/契约版本；重试同标识同内容复用提交结果，同标识异内容报冲突。语义去重还跨不同操作标识生效。

发布边界为保证引用自洽的最小单元，不等于全仓事务。内部引用目标/必需证据与主张一起可见，外部引用按模型A明确标记；部分失败可报告已发布单元与未完成单元，不能暴露悬空主张。中断后已发布结果可核验重读，未发布部分重试；不要求exactly-once网络传递。来源在构造后提交前变化由#12重新核对基点，拒绝当前有效发布或保留待核验，不猜更新政策。

路径大小写/分隔符/Unicode/行尾只影响证据定位与适配，不按host统一lowercase重键；语义内容去重/索引和差量比较应确定性完成，禁止调用模型判同。主张与来源核验观察分开记录，不把全量重写或长期历史默认为“增量”。
补证只指独立新依据追加；旧依据撤回或失效属于变化，不当纯补证绕开D03。幂等结果保留窗口待负载和恢复要求冻结；窗口过期后仍用语义去重防重复。批内循环引用允许共同发布，失败时该自洽单元整体不可见，不要求全仓事务。

补证合并候选规则：以模型A证据身份/原始来源及方法区分独立依据；同证据重复转换不是独立新证据。同证据标识不同载荷报契约冲突。追加不同证据关联不删除既有支持/反驳/限制角色；来源或方法配置/能力版本不同须保留，覆盖单独比较，不能简单合并声明完整性。该规则和原子单元未冻结时相关提交实现阻塞。幂等结果过期后可不返回原操作报告，但仍核已发布语义内容；恢复不要求永久日志服务。

验证反例：同操作ID提交内容A后用内容B重试→拒绝；两并发操作写同一规范内容→至多一份语义记录，另一得已存；循环A↔B中B证据写失败→整个自洽单元不对查询可见，重试只发布完整单元。


## Risks / Trade-offs

去重误抹配置/顺序/新证据会丢语义；读查再写并发须原子去重或等价约束；原子发布失败窗口由#12故障注入验证；写放大/元数据成本按#5计入，不宣称节省比例。

## Migration Plan

只规划；不改正式主规格、不apply、不archive。先冻结公共定义和未决重大选择，再整体审核，最后取得明确开发批准。唯一任务清单为本变更tasks.md，不维护第二套Superpowers计划。语言/混合边界、host和target按#5/#10矩阵取证；#5定义质量、端到端延迟/吞吐/资源及Token评价，数值未定不得宣称达标。

## Open Questions

D03重大更新政策必须用户选择；后端、原子单元大小、索引成本待D01/D02与支持矩阵；不承诺历史查询。
