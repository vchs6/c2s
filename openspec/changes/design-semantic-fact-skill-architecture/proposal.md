# Proposal

## Why

#6需要为后续查询、构造、获取与存储提供统一职责与契约归属，避免跨层重复身份、状态和裁真。原提案沿用当时已选模型A；该模型主轴已由ADR-0012更新，本提案现按语义实体身份/关系及观察视角解释。

## What Changes

- 提出查询驱动的逻辑组件与共享契约归属，内外范围分离。
- 以确定性转换、有效复用和必要局部模型减少实际Token。
- 部署、数据库、支持组合和变化写策略保持未决，不生成产品Schema。

## Capabilities

### New Capabilities
- `semantic-fact-orchestration`: 统一契约下的职责协作与范围传递。

### Modified Capabilities

无。

## Impact

供#7–#12引用。新架构是候选，证据与真实Battle见本Issue评审目录；用户确认仍仅共享context中内容。D01能力组合转为设计调查事项，D02评价方式已由ADR-0007明确，整体设计仍待收敛审核。仅规划，不实现或归档。

## 2026-11-02 系统需求确认接续

以ADR-0007及后续“当前一层=符合用户请求要求的顶层语义事实”为用户确认依据；需求与工具/接口等代理设计决定分开。人机双输出、缺口原因、查询触发与同主体补充、必要操作可执行及优化前后自评已明确。需求基线不等于全部设计已批准，当前仍不实施/归档。

## 领域模型对齐复核（2026-11-07）

领域模型对齐：公共实体契约、语义构造器和关系/实现/验证映射拥有规范身份；获取工具解析器只产出规范源码构造、观测与证据，不能独立生成另一套领域模型。E0–E4视角不对应部署组件或必需的五层处理管线。
