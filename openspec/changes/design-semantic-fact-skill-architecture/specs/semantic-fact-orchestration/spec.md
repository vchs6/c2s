# Semantic Fact Orchestration

## Purpose

为查询驱动的分层事实取得规定一致的逻辑职责与共享语义边界，使获取、复用、持久化和响应可协作，而不预设进程部署、数据库或产品实现语言。

## ADDED Requirements

### Requirement: 公共语义单点归属
系统 SHALL 复用公共领域契约定义主体身份、条件、主张、证据和诊断；获取器提交有来源的主张与局限，不自行重建分层身份或删除冲突来裁真。

#### Scenario: 多获取器看到同一操作
- **WHEN** 两个适配器取得同一主体不同尺度的信息
- **THEN** 复用同一主体身份及类型引用，保留证据与冲突信息而不产生按层副本

### Requirement: 内部范围与投影分离
系统 SHALL 分别维护用户请求范围、取得正确结果所需的有理由内部范围和最终响应范围；复用需核来源有效性，模型只处理必要且未解决语义。

#### Scenario: 顶层事实依赖外部声明
- **WHEN** 正确回答顶层请求需要读取一个依赖声明
- **THEN** 记录内部读取理由，仅响应请求所需事实，不自动展开依赖对象或全仓构造

### Requirement: 来源核验结果不得被吞并
系统 SHALL 将未核验、核验失败、已变化与已验证分别传递给消费方，不能因读取命中而声称当前有效；变化后的持久化依用户确认政策，不默认覆盖。

#### Scenario: 命中但无法核验来源
- **WHEN** 读取到已有事实且来源核验失败或缺乏能力
- **THEN** 保留事实和核验缺口，不无条件作为当前有效结果或自动覆盖存储
