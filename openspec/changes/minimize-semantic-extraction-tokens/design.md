# Design

## Context

已确认：共享context、ADR-0001/0002和两份主规格；模型A由用户选择但未批准实施。当前无产品实现或性能实测。新设计是候选；细节由授权范围内代理提出，不成为用户确认。讨论、异议及独立复核见本Issue评审目录。

## Goals / Non-Goals

在固定语义、正确性和证据约束下最小化实际输入/输出Token；非目标：只设限额、所有场景零Token、压缩掉必要事实或改变事实粒度。

## Approaches

候选确定性优先、按缺口局部模型与有效成果共享；替代每个请求对其所需源码直接模型分析，流程简单但重复输入输出；另一个可行替代是工具结构结果整包给模型统一转换，适配工作少但将确定性可转换内容重复交模型。都需同质量对照，不先声称一种必然更省或更快。

## Decisions

| 阶段 | 不需要LLM的工作 | 必要模型边界 |
| --- | --- | --- |
| 请求 | 结构请求校验/选择器路由 | 可选自然语言歧义解释，仅必要片段 |
| 定位/获取 | 文件定位、工具结构输出、版本配置核验 | 工具不能确定且请求必需的语义解释 |
| 分层构造 | 目录驱动转换、共享证据/结构、条件机械校验 | 缺口问题+相关局部代码+必要依赖，不按层重读 |
| 存储/复用 | 规范比较、去重、差量、适用/有效性核验 | 不用模型判同或决定覆盖 |
| 响应 | 有界投影、状态/引用序列化 | 只有请求确需且无法确定性呈现的解释，不重复生成全部事实 |

| 优化 | 省去的模型工作 | 保持内容与失效条件 |
| --- | --- | --- |
| 结构直接转换 | AST/元数据整包语言化再解析 | 保原始证据、模式/条件/覆盖；工具局限/配置不符则不宣称等价 |
| 跨层共享 | 同源码/结构在E2/E3/E4反复输入 | 共享来源不是五层内容都已取得，缺层语义仍补 |
| 有效事实复用 | 重复请求重提/重生成 | 核全部适用条件/来源/能力规则版本覆盖；变化或未核验不复用为当前有效 |
| 依赖差量 | 局部变更后全仓/全层重分析 | 用有证影响图，未知边界扩大必要核验或报缺口，不能漏影响 |
| 必要上下文包 | 整仓源码及重复提示/输出 | 包含问题、身份/上下文、最小相关证据、规则和缺口；缺必要依赖时请求有界补取或部分，不猜完整 |
| 分阶段成果复用 | 存储失败后再次模型构造 | 经核验成果在有效性与发布条件仍成立时重用，否则重建；重试成本不隐藏 |

输出只需新增主张及证据引用/局限，而非反复回显已知公共目录和整包旧事实；引用必须可解到保留内容，不把证据丢给不可复现外部链接。模型输出每次经公共契约/来源核验，核验失败和重试成本算入总量。共享提示前缀或供应商缓存仅辅助，不能以账单折扣代替实际输入输出Token下降。

验证设计沿用#5：同输入快照/请求/质量人工基准/语言host-target/模型版本，至少三组：A合理必要上下文直交模型，B确定性直转+局部模型但不启用跨请求共享/增量，C在B基础上加入有效共享/增量完整链路；工具整包模型可作第四组，不能替代B。不得故意将直模输入膨胀为无关全仓来制造收益；只有满足同等必要语义与证据的运行可比较收益。分别首次、重复复用、局变（含跨文件/配置变化）、失败重试；每一项机制做移除对照以归因。报告总/输入/输出Token、调用数、模型源码/上下文量、重复分析、质量/覆盖及端到端延迟/资源。固定请求不比较每事实比率，账单/缓存计费另列；未测或失败如实列不挑成功样本。

向#6回补职责不增加新模型服务：#10产生可转换结构与局限，#8规划复用/差量需求，#9确定性保存，#12协调有效性和失败恢复，#7确定性投影；本能力只拥有模型参与策略/上下文包与对照归因，避免重复实现其他能力。

预算、调用上限、退避与超限只停止不可承受工作并报告缺口；不当作优化机制。正确性/覆盖不能为降Token自动降低。若满足质量的候选比对照更多Token或更慢，保留测量，重大取舍提交用户，不宣称最优或隐藏成本。

## Risks / Trade-offs

确定性适配/核验也消耗CPU时间和维护成本；局部上下文可能漏非局部语义，需反例和必要补取。影响图不完备不能假装差量正确。Token优化不自动意味着延迟改善；无测量不冻结收益比例。

## Migration Plan

只规划；不改正式主规格、不apply、不archive。先冻结公共定义和未决重大选择，再整体审核，最后取得明确开发批准。唯一任务清单为本变更tasks.md，不维护第二套Superpowers计划。语言/混合边界、host和target按#5/#10矩阵取证；#5定义质量、端到端延迟/吞吐/资源及Token评价，数值未定不得宣称达标。

## Open Questions

D01/D02/D03、工具能力实证、质量基准及模型选择待整体审核。若实测出现质量/延迟/Token冲突，新增具体用户决策而非自动改变基线。
