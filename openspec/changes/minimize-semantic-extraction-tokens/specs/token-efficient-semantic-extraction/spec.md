# token-efficient-semantic-extraction

## Purpose

为分层语义事实的取得和维护规定实际减少LLM工作的方法及如实报告的前后对照边界，使首次构造、同次复用和后续查询补充都能检验，而不以计量限额或损失必要语义制造表面节省。

## ADDED Requirements

### Requirement: 模型参与须有必要性
系统 SHALL 优先评估确定性结构转换、跨层成果复用、差量处理及有界投影，仅将必要未解决语义与所需上下文交给模型，不以计量或调用限额代替减少模型工作。

#### Scenario: 结构事实可直接转换
- **WHEN** 工具已提供有证且满足请求的结构化声明
- **THEN** 经公共契约转换而不默认再让模型阅读整包或逐层重提

### Requirement: 上下文最小化保持必要语义
系统 SHALL 减少重复代码/规则/已存事实输入输出，同时保留必要条件、依赖、证据和局限；有效性或覆盖不明不得为降耗复用陈旧事实或猜完整。

#### Scenario: 后续查询依赖仍不明确
- **WHEN** 同次固定输入中后续查询所需内容存在未解析的跨语言依赖
- **THEN** 扩大有理由核验或报告影响缺口，不能仅取得本文件的局部信息就宣称全请求完整

### Requirement: 优化前后全链路对照
系统 SHALL 按#5相同输入、请求顶层范围、报告口径和环境，分首次/同次复用/后续查询补充/重试比较总输入输出Token、调用、上下文和重复分析，计入构造核验维护失败成本；列出取得内容及缺口变化，不要求严格语义正确率证明；未测不得宣称节省比例或所有情况零Token。

#### Scenario: 模型核验失败重试
- **WHEN** 局部模型输出首次不合格并重试
- **THEN** 两次输入输出及核验成本全部归原请求，不只报告成功那次成本
