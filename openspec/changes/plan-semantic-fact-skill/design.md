# Design

## Context

沿用已确认模型A、ADR与两份主规格。Issue事件仍不触发工作，用户本次明确授权会话在#4集合内持续规划。此前仅登记事项的说明是历史状态，不阻止本次显式启动。

## Goals / Non-Goals

**Goals:** 顺序管理#5–#13及上游依赖、候选/委托决定/用户确认，收集具体人工决策请求。每议题复用共享context与Issue输入，限制重复上下文，保持实际独立角色。

**Non-Goals:** 不实现产品、不承诺首期语言/平台或数值SLO，不将代理共识升级为用户批准。

## Decisions

各议题由主代理先brainstorming比较方案；按协议双方首轮、交叉质询与独立综合；原答复整理为论证摘要，不声称逐字转储或OS隔离。规划草案依据审阅修正后由主代理写入。重大范围、质量成本和存储变化策略显式参数化；下游不能把这些参数当已确认值。

共享决策请求集中docs/planning/program-2026-11-01/decision-requests.md，上游结论只保留必要摘要并注明权限。正式基线保持不变；未获用户决策的候选delta不自动同步。若某议题无法定案仍形成有边界提案和阻塞记录，不虚报开发就绪。

## Risks / Trade-offs

- [Risk] 数值/支持范围未定影响验收 → 参数化测量契约，最终不冻结为可开发集合。
- [Risk] 提案独立但概念漂移 → 共享定义归属和跨提案审核，由#13检查。
- [Risk] 为节省讨论Token省掉独立质询 → 控制输入/输出而非模拟角色或跳过关键审查。

## Migration Plan

依序完成下列规划任务，逐项验证，最终整体校验并直接main。规划集合未批准前不进入apply，不归档。
