# Proposal

## Why

用户已显式授权持续推进总计划#4及#5–#13。需要统一依赖、决策权限、共享定义和审核证据，防止分散提案互相冲突或误入产品开发。

## What Changes

- 依序头脑风暴、真实独立讨论和形成各能力变更；重要未决项记录决策请求，继续可推进部分。
- 汇总功能、非功能、语言/host/target与实际LLM Token最小化目标，不伪造测量。
- 审核整体规划后提交冻结候选；未获批准不开发，不归档。

## Capabilities

### New Capabilities

无。本变更只管理规划集合，skip_specs: true，不虚构产品能力。

### Modified Capabilities

无。正式模型/查询基线不变。

## Impact

仅OpenSpec规划与docs/planning、各Issue评审记录；不新增产品代码/Schema/依赖。能力提案各自拥有规格与唯一tasks，本清单只跟踪规划状态。

## 2026-11-02 系统需求确认接续

以ADR-0007及后续“当前一层=符合用户请求要求的顶层语义事实”为用户确认依据；需求与工具/接口等代理设计决定分开。人机双输出、缺口原因、查询触发与同主体补充、必要操作可执行及优化前后自评已明确。需求基线不等于全部设计已批准，当前仍不实施/归档。
