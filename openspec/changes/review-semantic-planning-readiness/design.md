# Design

## Context

用户显式授权依序持续规划，自动触发保持关闭。整体候选见overall-review.md、验收矩阵和待决清单。已确认规格约束不重开，新代理建议不冒充批准。

## Goals / Non-Goals

核功能、非功能、Token实际减量、语言/host/target、并发恢复与任务归属；输出可审核且可追溯的候选集合。非目标：替用户选重大范围/数值/更新政策，或将候选模块路径当已冻结API实施。

## Approaches

逐Issue局部批准易推进但不能发现跨能力矛盾；候选整体内容摘要审核可固定证据和范围但需清除关键未决。推荐后者：本次完成讨论/静态审核，关键决策未清前不冻结，不以旧#3令牌绕过集合审核。此为审核方法建议，不是用户已批准集合。

## Decisions

各变更spec delta与主规格分开；父计划只跟踪规划、子tasks跟踪未来产品任务，唯一本变更tasks跟踪审核。需求矩阵逐Requirement/Scenario连唯一tasks，禁止两套产品计划。

candidate bundle由已确认主规格、#3选定方案与本期所有提案/设计/delta/tasks、规则和必要决策文件组成，逐路径SHA-256加总摘要。manifest不含自身、Issue回复回执或最终验证报告以避免自引用；排除项不能改变规划语义。所有规范性内容修改均重算，摘要只是候选，freeze_status=not-frozen。未来用户决定写入工件→独立复核/严格校验→重新摘要→用户整体审核，再另取明确开发批准。任何来源变更导致旧冻结摘要失效，不暗中替换。

## Risks / Trade-offs

严格校验只查结构，需真实独立复核检查语义。文档调查不等运行支持，候选任务不等已执行。关键参数未决会阻塞冻结，但不阻止本轮形成完整有边界提案；技术占位类型/路径需在范围确定后细化，不允许直接实施。

## Migration Plan

本轮只产审核结果、待决和候选摘要，保持未冻结/开发未批准。用户决策及冻结需后续显式会话，不后台运行、不归档。

## Open Questions

ADR-0007已明确系统需求、必要操作及前后对照评价方式；D01技术能力组合由代理调查，D02不再等待用户给金标或数值；跨次来源更新另议。请求相对顶层投影规则、公共类型和工具/后端具体接口仍需代理技术细化。细化不重开确认行为；重大新增取舍再交用户。

ADR-0006后，分析期间项目不变是已确认前提，不再要求为同次增量构造先选择D03更新政策。跨次分析策略保留记录但不能借本句自动批准；本期整体仍未冻结、开发仍未批准。
