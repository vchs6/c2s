# C2S 使用说明：本地工具、其他 Skill 与安装责任

本文只说明**使用当前产出物**所需的依赖。当前 C2S 查询链路不依赖任何其他项目分析 Skill；安装本地工具与安装其他 Skill 是两件事。用户无需先手工装好全部依赖再让代理开始准备：具备终端、下载网络和可写目录的代理，可以在授权范围内代为安装并自检。

**C2S 程序本身没有自动安装器。** 下面的“代理可安装”指操作它的代理执行准备命令，不表示运行一次查询就会自动安装缺失软件、注册 Skill 或配置外部工具。

## 当前交付形态

当前仓库提供 Python CLI/API、契约、使用文档及验证脚本，通过仓库根目录的 `src`、`skill/src` 导入运行。按当前布局保留仓库自身文件，不要只复制 `skill` 子目录并假定它是独立安装包。它没有 Python 安装包配置，也没有 `skill/SKILL.md` 形式的宿主发现清单；尚不能承诺复制到某个宿主的 skills 目录后即可自动注册，或以某个斜杠命令直接调用。

现阶段可由用户在终端运行，或让具备本地命令执行能力的代理读取本说明并调用 CLI。代理宿主的自动发现、菜单注册和一键安装不是当前已交付能力。直接 CLI/API 使用不要求模型 API 密钥，也不调用其他 Skill 或远程模型。

已验证平台为 Linux x86_64；Python 正式版 3.12.x，实际验证过 3.12.5、3.12.14。Windows/macOS、其他架构和预发布解释器未验证。当前预发布版本字符串还存在已知 N1 解析异常，不能把 rc/dev 版本当作支持环境。

## 必需和条件必需的本地工具

| 工具或组件 | 何时需要、提供什么 | 用户是否必须手工安装 | 代理能否准备 |
| --- | --- | --- | --- |
| Python 正式版 3.12.x | 所有 CLI/API 查询的运行时 | 否；已有可用版本即可复用 | 可用用户目录运行时或环境包管理器安装；依赖终端、下载网络和写权限 |
| `jsonschema==4.26.0` | 契约与结构校验，必需 | 否 | 可在独立 Python 环境按 requirements-skill.txt 安装 |
| `tree-sitter==0.26.0`、`tree-sitter-rust==0.24.2` | Rust 语法与算法解析；当前导入路径下，Python-only 使用也安装完整最小依赖 | 否 | 可与上项一起安装；传递依赖由包管理器解析 |
| Python 标准库 `ast`、`tomllib`、`sqlite3` | Python 解析、TOML 清单、SQLite 存储 | 无需逐个安装 | 核验所用解释器已包含它们；不能用 pip 安装同名包来替代标准库 |
| `venv`、`pip` | 下述安装示例使用；不是查询时运行的外部分析器 | 否 | 通常随 Python 提供；精简系统缺少 venv/ensurepip 时，可改用可用的 uv 或补齐 Python 环境 |
| Git | 获取/更新 C2S 或上游源码、重建固定 Git 项目做验证时需要；普通目录查询不要求 `.git` | 否；源码已在本地时不必为基础查询安装 | 可在有权限时安装、克隆；私有仓库的访问授权由用户或平台提供 |
| Cargo 与可运行的 Rust 工具链 | 请求原生 Rust workspace 成员时条件必需；只做 Rust 静态语法解析不要求它们 | 否 | 可用 rustup 在用户目录安装并核验；已验证基线为 1.99.1，矩阵没有锁死 Cargo 精确补丁版本 |
| Code Review Graph 2.3.9 | 仅在本机需要生成其结构化图查询输出时选择使用；已有输出的导入不要求本机安装该包 | 否 | 可另建环境安装、按其接口生成输出；当前 C2S 不自动建图或执行这个外部后端 |

普通查询不需要 Node.js/npm、Docker、SQLite 服务或 sqlite3 命令行、Tree-sitter 命令行、tree-sitter-python、Rust 语言服务器。SQLite 通过 Python 标准库直接访问本地文件；不需要启动数据库服务器。

Python 包必须在运行 CLI 的同一个解释器环境中可导入。缺少最小包可能直接导入失败；不能把“缺 Cargo 可以报告缺口”理解成所有 Python 依赖都可以省略。

## 使用时是否需要其他 Skill

**当前必需的其他 Skill：无。** 当前构造器执行内置解析器、已接入的工具接口和已提供输出的专用解析器，没有自动调用其他 Skill 的链路。

| 名称 | 当前接入状态 | 使用当前产出物是否要安装 |
| --- | --- | --- |
| Serena | 矩阵 `candidate`；符号能力调研项，运行输出解析与完整枚举未验证 | 不需要；安装或注册 MCP 服务器不会使它自动参与 C2S 查询 |
| GitNexus | 矩阵 `candidate`；项目/调用图调研项，结果适配未验证 | 不需要；当前未接入生产构造链路 |
| `build-graph`、`explore-codebase` | Code Review Graph 上游配套 Skill 的候选记录；矩阵没有已验证的 Skill 结果解析器 | 不需要；C2S 不要求加载这些 Skill 来导入已有图 JSON |
| 其他项目分析 Skill | 没有登记、验证并接入的实现 | 不构成当前依赖，不能凭名称推断为已支持 |

这里区分工具与 Skill：Code Review Graph 的**结构化输出解析器**已点亮，不代表其上游两个 Skill 已接入；CodeGraph 1.6.2 虽有真实输出解析验证，仍因净覆盖收益未证明而保持 `candidate`。ast-grep、Semgrep、CodeQL 也只是候选工具；当前没有必要为使用 C2S 安装它们。

代理可以在宿主允许、来源明确且用户授权时安装其他 Skill，但这只是宿主配置行为。它不会自动补出 C2S 尚未实现的解析器、结果适配或生产选择能力。本说明不把候选项列为“用户装好后即可启用”的依赖。

## 谁负责准备环境

这里的“本地”是执行查询的机器。代理在云工作区安装，不等于用户个人电脑已经安装；要在个人电脑使用，需要该电脑上的可操作终端，或由用户执行文档命令。宿主操作系统由用户或平台提供，用户态依赖安装不等于代理有权更换操作系统。

用户或平台提供：能读取的源码/工作区、可写的环境与输出目录，以及代理执行命令的能力。需要下载时，环境须允许访问相应软件源；私有源码授权、宿主登录及只能由管理员开启的权限不能由代理凭空取得。

代理在这些条件具备时可以完成：检查现有工具、创建独立环境、安装最小包；按请求安装 Rust/Cargo 或外部图工具；执行版本自检和实际查询，报告未满足条件。已有会话安装授权时可沿用，无需让用户逐包手工操作。

没有本地终端或宿主安装接口的聊天代理，只能提供命令，不能声称已经替用户安装。网络/权限不足时应说明具体失败条件，不把失败写成已安装。C2S 不内置代理宿主，也不控制宿主给代理的权限。

## 最小安装：不需要其他 Skill

以下命令在 Linux 终端运行。已有仓库时跳过克隆；已有合格 Python 环境时可以复用。普通运行不要求初始化开发工具子模块。

```bash
git clone https://github.com/vchs6/c2s.git
cd c2s
python3.12 -m venv .local/analysis-venv
.local/analysis-venv/bin/python -m pip install -r requirements-skill.txt
```

Git 来源为本仓库，Python 包从公开 Python 包索引取得。首次安装需要下载网络；虚拟环境写入 `.local/analysis-venv`，pip/uv 还可能使用用户缓存和临时目录，不要求全局 pip 或 sudo。

`uv` 是可选的环境准备工具，不是查询依赖。没有合格 Python 而有可用 uv 时，代理可下载并选择正式版 3.12；例如 `uv venv --python 3.12 .local/analysis-venv`，随后 `uv pip install --python .local/analysis-venv/bin/python -r requirements-skill.txt`。能否自动下载取决于 uv 配置和网络条件，不是 C2S 自动安装功能。

在仓库根目录自检：

```bash
PYTHONPATH=src:skill/src .local/analysis-venv/bin/python - <<'PY'
import ast, tomllib, sqlite3, sys
import tree_sitter, tree_sitter_rust
from importlib.metadata import version
from c2s_skill.fact_query import execute_fact_query
if sys.version_info[:2] != (3, 12) or sys.version_info.releaselevel != 'final':
    raise SystemExit('需要正式版 Python 3.12.x')
print('Python:', sys.version.split()[0])
print('SQLite:', sqlite3.sqlite_version)
for name in ('jsonschema', 'tree-sitter', 'tree-sitter-rust'):
    print(name, version(name))
print('C2S 核心导入成功；此自检不要求安装其他 Skill')
PY
```

上面核验最小运行依赖。仓库的 `check_public_environment.py` 检查范围还包括 Node/npm 等开发工具，不用它决定纯 CLI 用户是否装齐最小运行环境。

## 首次查询与存储

仍在仓库根目录执行，将 `/path/to/project` 换成可读的实际项目目录：

```bash
PYTHONPATH=src:skill/src .local/analysis-venv/bin/python -m c2s_skill query \
  --root /path/to/project --select modules \
  --store /tmp/c2s-project.sqlite --format json
```

默认静态前端为 Python/Rust。C2S 以源码和少量说明材料形成带证据的来源记录与实体解释，不能把候选解释当作已证明的业务意图。查询 JSON 与 Markdown 都来自同一结构化结果。

事实档案保存在 SQLite：V2 模型作为 JSON 档案写入，身份注册与操作回执另表；不是一实体一文件。只有指定 `--store` 才持久化到该档案，`--cache` 是可选的另一个 SQLite 文件。数据库、缓存、`--output` 报告和图输出都应放在被分析目录外；输入保持固定，避免输出再次进入来源盘点。

查询退出码 `0` 表示本请求完整，`2` 表示存在缺口或保存失败，`64` 表示执行阶段无效输入；argparse 参数错误也可能返回 `2`。遇到 `2` 应查看 JSON 的 diagnostics/coverage，不能一概视为安装失败。伪代码是带静态不完整标记的实现参考。

## 条件能力：原生 Rust workspace

Cargo 不用于替代 Rust Tree-sitter；只有需要原生 workspace 元数据时才准备。代理可以通过 Rust 官方 rustup 安装用户目录工具链；安装会下载并写入 Cargo/rustup 目录，不要求修改项目源码。

已有 rustup 时，可在用户授权的工具链目录执行 `rustup toolchain install 1.99.1 --profile minimal`，再核验 `rustup run 1.99.1 cargo --version`。从零准备 rustup 的方式依宿主而定，来源为 Rust 官方安装渠道，不能假定每个终端都已装好 rustup。

对本仓库已有的本地工具链，示例为：

```bash
CARGO="$PWD/.local/cargo/bin/cargo" \
CARGO_HOME="$PWD/.local/cargo" RUSTUP_HOME="$PWD/.local/rustup" \
RUSTUP_TOOLCHAIN=1.99.1 \
PYTHONPATH=src:skill/src .local/analysis-venv/bin/python -m c2s_skill query \
  --root /path/to/rust-project --select workspace-members \
  --store /tmp/c2s-rust-project.sqlite --format json
```

这些路径须指向已安装的工具链；系统安装可使用 PATH 中的 Cargo，不照抄不存在的 `.local` 路径。仅有 rustup 代理文件不等于 Cargo 可运行。实际命令是 `cargo metadata --format-version 1 --no-deps --offline`；需要提前准备可用工具链及项目条件，失败会报告 workspace 缺口，不自动联网补装或执行完整构建。

## 条件能力：导入已有图查询输出

已有 Code Review Graph 2.3.9 的 `query_graph` 调用者/被调用者结构化 JSON 时，导入不要求本机安装 Code Review Graph、MCP 服务或任何配套 Skill：

```bash
PYTHONPATH=src:skill/src .local/analysis-venv/bin/python -m c2s_skill query \
  --root /path/to/project --select function:run \
  --graph-output /tmp/c2s-graph-query.json --graph-version 2.3.9 \
  --store /tmp/c2s-project.sqlite --format json
```

输入需符合已验证解析器的查询协议，不是任意知识图谱 JSON。C2S 检查路径、版本和截断，保存原始输出；索引新鲜度不能证明时继续报告缺口，不因图文件存在就宣布完整。

没有图输出而希望在本机生成时，代理可按需要在独立环境安装 `code-review-graph==2.3.9`，再按该工具接口建索引并导出指定查询响应。C2S CLI 当前没有建图/导出命令，也不会自动启动该工具。API 的 `tool_runner` 允许调用者提供执行回调，外部执行和宿主接口准备仍由调用者负责。没有这些条件时应保留关系缺口，不能声称安装某个候选 Skill 就解决了它。
