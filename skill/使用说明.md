# codesemantics 使用说明

## 跨语言定位与提取覆盖

codesemantics以语言无关的事实模型和查询接口描述项目组织、语义实体、属性关系、实现与测试映射及算法参考，面向跨语言项目理解。具体自动提取范围由工具能力矩阵中已接入、解析并验证的能力决定；当前内置源码解析与算法投影已验证Python、Rust。其他语言需要相应语言前端或工具结果解析器，未接入或未验证时保留请求覆盖缺口，不能仅凭跨语言定位宣称已完整取得事实。Python运行依赖与被分析项目使用的语言分别说明。

## 准备与自检

安装程序部署标准Agent Skills目录并准备独立Python环境。安装命令、各助手目录与--target用法见[README](README.md)。默认用户级安装可将工具放在被分析项目之外；项目级使用--scope project --project-dir /实际项目目录，完整盘点该项目时也会包含其Skill文件，不会自动忽略它们。可以运行`python3 install.py --help`查看参数。

没有其他必需项目分析Skill。Serena、GitNexus和图提供方的配套Skill未接入自动构造链路，安装它们不会自动补出结果适配。CodeGraph、ast-grep、Semgrep、CodeQL也不构成当前运行前提。

| 组件 | 何时需要 | 准备责任 |
| --- | --- | --- |
| 正式版Python3.12 | 全部查询 | 安装器复用合格解释器，支持--python；存在uv时可由其准备。没有相应工具时代理可安装，或由用户/平台提供 |
| jsonschema4.26.0、tree-sitter0.26.0、tree-sitter-rust0.24.2 | 最小导入依赖，不因被分析项目语言不同而省略 | 默认由安装器在Skill内的.venv安装，--no-runtime跳过此步骤 |
| ast、tomllib、sqlite3 | Python解析、TOML与本地数据库 | Python标准库，不单独安装同名包或数据库服务 |
| Git | 获取源码或固定项目验证 | 已有普通目录可直接分析，无需.git；代理有权限时可安装与获取源码 |
| 可运行Cargo | 原生workspace成员 | 条件需要；代理可通过Rust官方rustup准备。仅有rustup代理文件不代表工具链可用 |
| Code Review Graph2.3.9 | 在本机生成对应图查询输出 | 可在独立环境准备；已有结构化响应的导入不需要本机图包或配套Skill |

用户或平台提供可读源码、可写目录、必要下载网络和终端执行能力。私有源码授权和助手登录由用户/平台提供。没有本机访问能力的聊天代理不能声称已在用户电脑安装软件。查询使用的Python依赖必须在同一个解释器环境可导入；缺失时先完成环境准备。

自检与查询均使用本文件所在Skill目录的绝对路径；scripts中的入口会自行定位运行文件和.venv，不要求切换当前项目目录：

```bash
python3 /技能目录/codesemantics/scripts/check.py
```

## 来源与函数查询

```bash
python3 /技能目录/codesemantics/scripts/codesemantics.py query \
  --root /项目目录 --select modules --store /项目外/facts.sqlite --format json
python3 /技能目录/codesemantics/scripts/codesemantics.py query \
  --root /项目目录 --select function:Owner.run --store /项目外/facts.sqlite --format markdown
```

可选选择器包括classes、functions、definitions、imports、constants、all-declarations、local-bindings等；名称不是业务语义的自动证明。固定中文表单如“有哪些类”可规范化为请求，自由文本超出支持表单时报告缺口。

## 语义实体与结构化请求

```bash
python3 /技能目录/codesemantics/scripts/codesemantics.py entities \
  --root /项目目录 \
  --request '{"target":{"kind":"DataEntity","name":"Record"},"detail":"self"}' \
  --store /项目外/facts.sqlite --format json
```

请求可指定view、target、facets、detail与expandDepth。self返回目标自身已取得属性与直接关系，list返回目标清单；expandDepth默认为0，最大8。不默认递归附送子实体或无关关联对象。语义实体候选及推导保留依据与暂定状态，源码模块可独立查询。

## 算法与伪代码

```bash
python3 /技能目录/codesemantics/scripts/codesemantics.py algorithm \
  --root /项目目录 --source src/parser.py --function parse \
  --store /项目外/facts.sqlite --format json
```

按明确请求展开函数算法；--all-functions请求全部已发现函数。伪代码具有源位置和不完整标记，不承诺语义等价、完整控制/数据流或复杂度推断。

## 原生workspace

准备可运行的Cargo后，使用PATH或CARGO指定可执行文件；安装在用户目录的工具链可同时配置CARGO_HOME/RUSTUP_HOME和已安装的RUSTUP_TOOLCHAIN。

```bash
python3 /技能目录/codesemantics/scripts/codesemantics.py query \
  --root /Rust项目目录 --select workspace-members --store /项目外/rust-facts.sqlite
```

命令执行`cargo metadata --format-version 1 --no-deps --offline`，不执行完整构建、不解析完整依赖闭包。先准备工具链和项目条件；元数据失败保留workspace缺口，不在查询阶段补装软件。验证基线Cargo1.99.1，当前矩阵不锁死其精确补丁号。

## 导入图输出

```bash
python3 /技能目录/codesemantics/scripts/codesemantics.py query \
  --root /项目目录 --select function:run \
  --graph-output /项目外/graph-query.json --graph-version 2.3.9 \
  --store /项目外/facts.sqlite
```

输入须符合Code Review Graph的query_graph调用者/被调用者查询协议，不接受任意知识图谱JSON。导入时不要求安装提供方软件或Skill；版本、路径、截断与新鲜度缺口仍会检查和保留，原始工件一并保存。显式新图输入不会被响应缓存屏蔽。

需要生成图输出时，由调用者或代理通过该工具接口准备；本CLI不自动建图或启动外部服务。API可通过tool_runner提供执行回调，结果仍经已接入解析器处理。

## 输出、存储与备份

JSON和Markdown来自同一事实集；响应含items、sourceRecords、claims、evidence、coverage、diagnostics、persistence。退出0表示请求完整，2表示事实缺口或保存失败，64表示执行阶段无效输入；参数解析错误也可能返回2。应结合诊断解释，不将所有2都视为安装失败。

只有指定--store才持久化事实档案。SQLite中完整模型以JSON保存，身份注册和操作回执另表；--cache是另一个可选SQLite响应缓存。数据库、缓存、--output报告和图输出放在被分析目录之外。完整目录内容参与指纹，不默认忽略node_modules/target等路径。

同输入/配置/范围的有效覆盖可复用；相同失败重试不重复累积等价取得状态，操作回执保留审计轨迹。失败或取消不抹除先前取得的部分覆盖；缺失证据、主张前提或工件有明确诊断。配置或输入改变后不复用不适用结果。

API备份示例（使用Skill的.venv/bin/python运行，并将runtime/src、runtime/skill/src加入PYTHONPATH）：

```python
from pathlib import Path
from codesemantics.semantic_store import SemanticEntityStore
from codesemantics.archive_backup import backup_entity_archive
receipt = backup_entity_archive(SemanticEntityStore('/项目外/facts.sqlite'), Path('/项目外/facts-backup.sqlite'))
```

备份源须存在，目标须不存在；SQLite完整性与逐表读回通过后返回verified及摘要。恢复前停止写入，使用完整备份作为档案路径，不覆盖正在使用的数据库。
